## 基本思想

- **「書くのは自由・見た目は全員無料・AI に課金」**
- テーマは全ユーザー全テーマ無料（デザイン＝差別化軸は広く届ける。課金対象にしない）
- ユーザーにストレスを与える制限は最小限に。物理ノートの比喩（使い切ったら新しいのを買う感覚）
- 招待制の小規模コミュニティ前提。客単価で収益を確保する
- 打倒 Notion: AI 付きでも Notion AI（月 $10）より安い水準を狙う

## コスト構造（課金設計の根拠）

変動して・ユーザー単位に帰属できるコストは**実質 LLM トークンのみ**。

| 場所                             | コスト性質                           | ユーザー帰属    |
| -------------------------------- | ------------------------------------ | --------------- |
| Cloud Run / Supabase / Vercel    | ほぼ固定・無料枠（今の招待制規模）   | △〜✕            |
| Sentry / UptimeRobot / テーマCSS | 固定・ほぼゼロ                       | ✕               |
| **LLM API（Claude）**            | **トークン従量・唯一青天井に伸びる** | ⭕️ 完全に測定可 |

→ 従量課金は **AI トークン原価をパススルー＋固定マージン上乗せ**で素直に実現する。
インフラ固定費は下限料金に薄く吸収させる。

## 課金モデル v2（確定仕様）

```
        ¥500 ────────────── ¥2000（デフォルト天井・ユーザー変更可）
   下限（¥500ぶんのAI込み）    従量ゾーン          上限でハードストップ
```

| 要素             | 仕様                                                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| **下限**         | 月 ¥500。**¥500 ぶんの AI 利用が込み**（席代ではない）。固定マージン＋インフラ基礎体力を保証                                  |
| **従量**         | ¥500 を超えたぶんは `LLM トークン原価 ×1.5`（マージン 50%）で積み上げ。マージンは為替・トークン見積もり誤差のバッファも兼ねる |
| **上限（天井）** | デフォルト ¥2000。ユーザーが自由に設定可。**到達でハードストップ**（AI 停止）。停止時は「天井を上げる？」の引き上げ導線を提示 |
| **回数制限**     | **撤廃**（旧 v1 の 30 回/冊・100 回/全体は廃止）。純・従量へ                                                                  |

- モデルの形は Anthropic / OpenAI の API 課金（最低コミット＋従量＋ハードリミット）に近い
- ハードストップにより「青天井が怖い」を構造的に解消する

## 課金単位

- **AI はノートブック課金単位に紐づく**（ノートブック外のメモでは AI を使えない）
- 無料枠: メモ無制限・ノートブック 3 冊（各 3 万文字）・全テーマ無料・AI なし
- 容量判定は「今入っているメモの合計」で行う（メモを外せば空く）。文字上限は無料・有料共通で 1 冊 3 万文字

## 課金方式: 前払いウォレット（確定）

従量は **前払いウォレット残高消費**で実装する（Stripe メータード後請求は採らない）。

- 月額 ¥500 のサブスクで **¥500 ぶんのウォレット残高（クレジット）を毎月付与**
- AI 利用のたびに `トークン原価 ×1.5` を残高から減算する
- 残高が尽きたら**追加チャージ**（天井までの範囲で自動チャージ、または手動チャージ）
- 天井（spendingCapYen）= その月にチャージ・消費してよい上限。到達でハードストップ
- 採用理由: 未収リスクなし／天井ハードストップが構造的に自然／会計がシンプル（個人開発・招待制規模に最適）

## 決済（Stripe）

- 買い切り（ノートブック単品/パック）: **Payment Intent**
- サブスク（月額 ¥500・ウォレット付与）: **Subscription**
- 追加チャージ（ウォレット残高の積み増し）: **Payment Intent**（都度課金）
- 価格・通貨は `jpy`

## データモデル（実装ターゲット・未実装）

> 以下は**計画**。実装時に Prisma スキーマへ追加する。現状 `User` / `Notebook` に課金カラムは無い。

```prisma
// User 拡張
stripeCustomerId      String?
subscriptionStatus    NONE | ACTIVE | CANCELED | EXPIRED
subscriptionExpiresAt DateTime?
spendingCapYen        Int @default(2000)   // ユーザー設定の天井（当月チャージ・消費の上限）
walletBalanceYen      Int @default(0)      // 前払いウォレット残高（AI 利用でここから減算）
notebookCredits       Int @default(0)      // 付与の未使用分（買い切りパック等）

// Notebook 拡張
characterLimit Int     @default(30000)
isFree         Boolean @default(true)
purchaseId     String?  // → Purchase

// Purchase（新規）: type = SINGLE_NOTEBOOK | NOTEBOOK_PACK | SUBSCRIPTION
//   amount / currency('jpy') / status(PENDING|COMPLETED|FAILED|REFUNDED)
//   stripePaymentIntentId? / stripeSubscriptionId?

// AiUsage（新規・課金根拠）: userId / notebookId / action / tokensUsed / costYen / createdAt
//   action = "proofread" | "summarize" | "qa" | "ghostwrite" | ...
```

- **`AiUsage` が従量消費の唯一の根拠**。AI を呼ぶ全パスで必ず計上する（トークン数＋換算後の円コスト＝`原価×1.5`）
- 課金フロー: `AiUsage.costYen` を `walletBalanceYen` から減算する。残高 < 次回コストならブロック（ハードストップ）
- 月次サイクル: サブスク更新時に ¥500 ぶんを `walletBalanceYen` に付与。`spendingCapYen` は当月の自動チャージ・消費の上限として機能

## 不変則（実装時に守ること）

- AI 実行前に**ウォレット残高と天井を必ずチェック**し、残高不足・天井超過の呼び出しはブロックする（ハードストップ）。停止時は引き上げ導線を提示
- AI を呼ぶ全機能（手動 `/ai-*` も自動生成系も）は `AiUsage` 計上を経由する。計上漏れ＝請求漏れ
- **自動生成系（朝のダイジェスト等）が最も天井に当たりやすい**。バックグラウンド生成は実行前に必ず天井ガードを通す
- テーマは課金対象にしない（不変則。LP・差別化軸を毀損するため）
- 課金状態の真実の源泉は Stripe（webhook）と DB。フロント Zustand へ課金状態をコピーしない（既存アーキ不変則に準拠）
