# ブレインストーミング - 2026-06-02

## セッションの文脈

- 出発点となった課題感: 「TipTap のエディタで Markdown が WYSIWYG で効かない。`# ` 等を打っても変化しない」
- 議論の流れ:
  - 現状エディタはツールバーのボタン操作中心（太字・H1/H2・リスト・引用）。
  - StarterKit は本来 Markdown 入力ルール（input rules）を内蔵するが、**打っても変化しない＝input rules が潰れている**症状を確認。
  - 有力な原因仮説: `RichTextEditor.tsx` の content 同期 `useEffect`（`editor.commands.setContent(content)`）がタイプ中に走り、ProseMirror のトランザクションをリセットして `# ` 等の変換成立を阻害している可能性。
  - 理想の書き心地を確認 →「ガッツリ（Notion / Bear っぽいリッチな入力体験）」を希望。

## 有力候補

**「TipTap Markdown WYSIWYG エディタ強化」を1機能として起票**するのが妥当。

- まず **#1（input rules 復活バグ修正）が全ての土台**。これが直らないと #2 以降が成立しない。
- #2 基本ショートカット網羅で「Markdown が効く」状態を担保。
- #3 `/` スラッシュコマンドでリッチな入力体験へ。既存の `/` mention（ノートブック参照）との共存設計が論点。
- #4〜#6 は段階的に追加（フェーズ分け）。

論点メモ:

- `setContent` 同期と input rules の両立（タイプ中は setContent を走らせない / `emitUpdate: false` や差分判定の見直し）。
- 自動保存（編集停止2秒）との整合。HTML 保存のままか、Markdown 保存に寄せるかは別途検討。
- 既存 `/` トリガー（Mention=ノートブック参照）とスラッシュコマンドメニューの衝突回避。
