## セッションの文脈

- 出発点となった課題感（ユーザーの言葉）: 「現状は tiptap で markdown 形式のみの対応で、色付けやカードを挿入したり、あんまりリッチなメモにすることはできない」「めちゃくちゃリッチなメモがユーザ登録時点で作成されていたら『え！？こんな良い感じのメモ書けるの？』ってなるから、そういう方向性で考えていきたい」

## 前提（調査で確認した事実）

- エディタ現状: Tiptap 3.22.2 + StarterKit（H1〜H3 / 太字 / 斜体 / 取り消し線 / リスト / 引用 / リンク autolink）+ CodeBlockLowlight + TaskList/TaskItem + スラッシュコマンド9種 + `[[ノートブック参照]]`。**色・ハイライト・コールアウト・表・トグル・画像・埋め込みは未対応**（= markdown 相当が上限）
- content-jsonb-migration が implementation-validated（2026-07-04）: 本文は Tiptap JSON ネイティブ。カスタムノード追加の障壁が最小のタイミング。オフライン層 v2 も JSON 前提で整備済み
- `createEditorExtensions.ts` が編集/公開表示の拡張セットの単一情報源 → 新ノードは構造的に公開ビュー往復一致の枠組みに乗る
- `Memo.notebookId` は nullable → ウェルカムメモはノートブック無しで1枚シード可能
- 過去の教訓: onboarding-experience（テーマ選択＋サンプルメモ生成モーダル）を「早すぎた」「毎回表示されて邪魔」で 2026-06-18 に全削除（onboarding-removal）。今回は「モーダル割り込み」ではなく「登録時点でデータとして置いてある」ため削除理由に抵触しない別アプローチ。削除済みのサンプルメモ生成コードは git 履歴に残っており実装の参考にできる

## 決定事項・設計原則

1. **色はテーマ対応パレット**: CSS 変数のセマンティックカラーで、mori/umi/yoru/asa の明暗どちらでも AA コントラストを守る（theme-immersive-world の機械検証文化を踏襲）。「どのテーマでも綺麗に発色する色」を差別化ポイントにする
2. **ウェルカムメモは再現可能要素のみ**: ユーザーがまだ作れない要素（画像等）は載せない。「こんなの書けるの!?」→ 触って「私もできた！」までをワンセットで成立させる
3. **ウェルカムメモの題材は「リアルな実用サンプル」**: 第一候補は旅の計画メモ（模索＝人生の冒険のブランドとも整合し、コールアウト/色/表/トグル/チェックリストを自然に全部載せられる）
4. **シードはメール登録＋OAuth 初回ログインの両経路**で行い、冪等にする（既存ユーザーに再生成しない）。本文は Tiptap JSON の固定定数（バージョン管理）
5. **新ノード追加時の追随スコープ**: `prosemirrorText.ts`（検索テキスト抽出）・公開ビュー（PublicMemoRenderer）・オフライン層の3点を必ず含める
