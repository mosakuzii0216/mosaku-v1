# ブレインストーミング - 2026-06-25

## セッションの文脈

- **出発点となった課題感（ユーザーの言葉）**:

  > 「ガチでカッコよくてオシャレでイカしたテーマじゃないから、メモを取ろう・見に行こうって思えない。メモするのが面倒なのは MCP を生やして解決したけど、"見に行きたくなるビジュアル"になってないのが触らない原因」
  > 「Tailwind の Material っぽい、よくあるボタンの UI が萎える。メモ一覧も編集画面もありきたりすぎる」
  > 「テーマを開いた瞬間から全体に適用されることが、"好きな世界に入りたい・戻ってきたい"のモチベになるんじゃないか」
  > 「（没入と質感は）両方セットじゃないと意味ない」

- **議論の流れ**:
  - 「書く労力」は MCP で解決済み。残る本丸は **"見に行きたくなる引力（pull）"** の欠如。
  - 萎えポイントの局所化 → **(a) アプリを開いた瞬間の一覧・ホーム・サイドバーが真っ白**（＝玄関が既製品 UI）。現状テーマはメモ本文面（`.memo-title`/`.memo-content`）だけに乗っており、シェルは未テーマ。
  - 「開きたくなる」当たり = **ポケポケ（ポケモンカードアプリ）の質感**。色ではなく、テクスチャ・奥行き・清潔感・"既製品っぽくないコンポーネント"。
  - ユーザー自身が核心に到達 → **テーマ＝"入る世界"。開いた瞬間から全体がその世界＝戻ってくる動機**。
  - 2 つの欲求は **A.全体没入スコープ拡張** と **B.脱・ありきたり質感** で、**セット必須**と確認。
  - 既知の地雷を共有 → 既存 spec `mosaku-brand-theme` の Phase A で「全体適用」を一度実装→**ヘッダー文字消失でロールバック**済み。雑にやると壊れる＝だからこそ設計してやる価値のある宿題。

## 有力候補

**森（mori）フラッグシップを"入る世界"としてフル没入＋質感でフルリライト（垂直スライス・深さ優先）** に合意。

- 理由:
  - 没入(A)と質感(B)は**セット必須**とユーザーが明言 → 1テーマで両方フルに実証するのが最短で「うわ、この世界に住みたい」を出せる。
  - 「全体適用」は過去にロールバック済みの**地雷原**。1テーマで詳細度・トークン設計を正しく確立してから横展開すれば、4テーマ分の地雷を一度に踏まない。
  - 過程で **シェル適用基盤（#3）＋質感コンポ層（#2/#4）** が出来上がり、残り3テーマ（海・夜・朝）は相乗りで展開可能。
  - 森は既にフラッグシップ（`mosaku-brand-theme` の主役）。世界観の資産（深緑グラデ・霧・葉エフェクト）を土台にできる。

## 実施メモ

- **選択した機能**: 森フラッグシップの全体没入＋質感フルリライト（仮称 `theme-immersive-world`、第一スライス＝森）
- **既存 spec との関係**: `mosaku-brand-theme`（implementation-validated）の Phase A「全体適用」を、セマンティックトークンで正しくやり直し＋「質感」軸を新規追加する**後継/拡張**。新規 spec として起票が妥当。
- **次のステップ**: `/kiro:spec-init` で新規スペック起票 → requirements で「没入スコープ」「質感の定義（ポケポケ級の具体化）」「ロールバック回避のトークン設計」「森→他3テーマ展開の基盤要件」を固める。
- **論点メモ（requirements で詰める）**:
  - 「質感」を測れる言葉に落とす（テクスチャ/奥行き/余白/タイポ/マイクロインタラクション）。ポケポケのどの要素を翻訳するか。
  - シェル適用の詳細度・トークン設計（friction log「ヘッダー文字消失」の再発防止を要件化）。
  - 外部JSライブラリ追加ゼロ方針（軽量メモアプリ）との両立。
