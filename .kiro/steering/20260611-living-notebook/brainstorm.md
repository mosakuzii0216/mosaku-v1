## セッションの文脈

- 出発点となった課題感:
  - 「人間がメモを書かなくても、AI が書いて読む近未来のメモアプリにしたい」（ユーザーの言葉）
  - 既存の AI 構想（`/ai-proofread` `/ai-summarize` `/ai-ask`）は全て「人間が書く → AI が手伝う」。その先の「AI が主体的に書く・読む」へ発想を転換したい
  - 並行して、課金モデル（特にサブスク）を「使った分だけ・固定マージンは確保」へ見直したい
- 議論の流れ:
  1. mosaku のコスト構造を棚卸し → 変動・ユーザー帰属できるコストは実質 LLM トークンのみと確認
  2. 課金モデルを従量制（v2）へ再設計
  3. 「AI が書く・読む」機能を 4 方向で発散 → 3 方向に収束 → 共通コンセプト「生きるノートブック」を発見
  4. 最初の spec（MVP）を **AI ゴーストライター**に決定

## コスト構造の棚卸し（前提整理）

| 場所                  | 役割                   | コスト性質                               | ユーザー単位で測れる |
| --------------------- | ---------------------- | ---------------------------------------- | -------------------- |
| Google Cloud Run      | バックエンド（NestJS） | リクエスト/vCPU 秒の従量。今はほぼ無料枠 | △（激安）            |
| Supabase              | PostgreSQL             | 容量/接続で段階課金。ほぼ固定            | △                    |
| Vercel                | フロント配信＋関数     | 帯域/関数実行。ほぼ固定・無料枠          | ✕                    |
| Sentry / UptimeRobot  | 監視                   | イベント枠。固定                         | ✕                    |
| テーマ CSS            | 静的配信               | ほぼゼロ                                 | ✕                    |
| **LLM API（Claude）** | AI 機能の本体          | **トークン従量。唯一青天井に伸びる**     | ⭕️ **完全に測れる**  |

> 結論: 変動して・ユーザーに紐づけられるコストは実質「LLM トークン」だけ。
> よって「使った分だけ請求＋固定マージン」は AI トークン原価のパススルー＋上乗せで素直に実現できる。

## 課金モデル v2（確定 / 2026-04-21 のサブスク定義を更新）

```
        ¥500 ────────────── ¥2000（デフォルト天井・ユーザー変更可）
   下限（¥500ぶんのAI込み）    従量ゾーン          上限でハードストップ
```

- **下限 ¥500**: 使わない月でも ¥500。**¥500 ぶんの AI 利用が込み**（席代ではない）。これが固定マージン＋インフラ基礎体力を保証
- **従量**: ¥500 を超えたぶんは LLM トークン原価 ×(1+マージン) で積み上げ
- **天井**: デフォルト ¥2000、ユーザーが自由設定。**到達でハードストップ**（AI 停止 → 翌月 or 自分で上限引き上げ）。青天井の不安を構造的に消す
- 旧「回数制限（買い切り 30 回/冊・サブスク 100 回）」は撤廃し、純・従量へ
- 課金根拠は既存の `AiUsage`（tokensUsed トラッキング）テーブルをそのまま流用
- モデルの形は Anthropic / OpenAI の API 課金（最低コミット＋従量＋ハードリミット）に近く、SaaS として筋が良い

## 有力候補 — コンセプト「生きるノートブック (Living Notebook)」

選んだ 1・2・4 は別機能ではなく、1 つのループの 3 側面だった:

```
   ④ AI対話がメモ化      → ノートに「素材」が溜まる（入力）
        ↓
   ② AIゴーストライター   → 断片を本文に膨らます（変換）
        ↓
   ① 朝のダイジェスト     → 溜まった全部をAIが読んで再構成（出力）
        ↓
        （また④へ…）
```

- 共通の土台: (a) AI がノート文脈を読む（RAG/文脈注入）、(b) AI がノートに書き込む、(c) 従量ウォレット
- 土台を最初に作れば後続が安く乗る → **②ゴーストライターを MVP**にして土台を最小で立ち上げる
- コスト観点: ②④は人がトリガー（予測しやすい）。①は AI が自動で焼く → **¥2000 ハードストップが最も効くのは①**
