# ブレインストーミング - 2026-06-15

## セッションの文脈

- 出発点となった課題感（ユーザーの言葉）:
  - 「MCPのエンドポイントを作ることが、メモはめんどいけど大事だと思ってる人への必殺技かもしれない」
  - 対象は **ユーザー自身**（夢さん）。仮想ユーザーではなく自分ゴトの課題
- 課題の核心（深掘りで判明）:
  - **「そもそも書く行為自体がめんどい」**。自分でゼロから書かない
  - 実際のスタイル = **AIと壁打ち → 最終的に markdown で書き出させる → それがメモ**。書く作業はAIとの会話の中で既に終わっている
  - その markdown は今 **ChatGPT/Claude の履歴に置きっぱなし**（option 2）→ 後で見つけられない＝**書いたのに資産にならない**
- Obsidian について:
  - 惹かれたのは「ローカル/データ所有」より **「AIが使えて賢くメモできそう」** という期待（本人はObsidian未使用）
  - → 本当に欲しいのは "AIが自分のメモを使える状態にしておくこと"
- 読み書きの優先度: **「両方セットで初めて必殺技」（option 3）** を選択

## 議論の流れ

1. MCP とは何かを初心者/エンジニア両面で解説（AIに外部アプリを"道具"として持たせる共通規格）
2. 「メモがめんどい瞬間」を特定 → **書く行為自体**（壁打ち→markdown出力スタイル）
3. 成果物 markdown の行き先 → AI履歴に死蔵されている問題を発見
4. 欲しいのは read + write 両方 = mosaku を **AIの外付け脳みそ（長期記憶）** にすること
5. 利用ツールを特定 → **Claude Code がダントツ本命**
6. v1 スコープを `create_memo` + `search_memos` に確定

## 確定した必殺技コンセプト

> **mosaku = AIの「外付け脳みそ（長期記憶）」**
>
> 普段使うAI（Claude Code等）と壁打ち →
> ① 結果が MCP 経由で mosaku に自動着地（**書く手間ゼロ** / write）
> ② 次の壁打ちでAIが過去メモを思い出して使う（**賢くなる** / read）
> → 「書く行為」が消え、メモが勝手に資産として育つ
>
> **「めんどい（書く）」を消して「大事（資産）」だけ残す**構造。
> Obsidian が「手で育てる庭」なら、mosaku+MCP は「AIが勝手に手入れする庭」。

## ★ ビジネス上の重要発見（課金設計に影響）

- Living Notebook（既存AI構想）: **mosakuサーバーがClaude APIを叩く＝トークン代をmosakuが払う** → 従量課金が必須だった
- **MCP は逆**: 壁打ちするのはユーザー自身のAI（Claude Code等）。**トークン代はユーザーのAI契約が払う**。mosakuは保存・読み出しするだけ＝**変動コストほぼゼロ**
- → MCP は「AI機能なのに mosaku がトークン代を払わなくていい」唯一の入口。**サブスク込み / 定額機能として提供可能**。`monetization.md` の従量モデルとは別枠で扱える

## 利用ツールと接続方式

| ツール                  | 優先     | MCP対応          | 繋ぎ方                                        |
| ----------------------- | -------- | ---------------- | --------------------------------------------- |
| **Claude Code**         | ◎ 本命   | ネイティブ       | `claude mcp add --transport http <url>`       |
| Claude スマホ/claude.ai | ○        | Custom Connector | アカウントにコネクタ登録 → スマホからも利用可 |
| Gemini スマホ           | △ 後回し | 弱い             | v1対象外                                      |

- **作るものは1個**: mosaku の **リモート MCP サーバー（Streamable HTTP + OAuth 2.1）**
- 認証は既存の **JWT + OAuth 基盤**に乗せる（地盤あり）
- ホスト先は backend（NestJS / Cloud Run）

## 有力候補

**mosaku リモート MCP サーバー（v1: `create_memo` + `search_memos`）** で合意。
理由: ①夢さんの根本課題（書くのがめんどい）を構造的に解消、②既存のJWT/OAuth基盤・メモ/ノート基盤を流用でき実装現実的、③変動コストゼロで課金設計を圧迫しない、④本命のClaude Codeで即体験できる。

## 設計上の論点（spec で詰める）

- **search の実装**: v1はPostgres全文検索（キーワード）で十分か、最初から埋め込み（semantic）まで行くか
- **OAuth 2.1 フロー**: MCP標準の Authorization Server Metadata / Dynamic Client Registration をどこまで実装するか
- **保存先の既定**: notebook 未指定時のデフォルト（無料枠ノート / Inbox 的な受け皿を作るか）
- **所有権**: `create_memo` / `search_memos` とも `AuthorizationService.validateOwnership()` でユーザー境界を担保
- **不変則準拠**: サーバー側実装なので apiClient 経由ではなくサービス直呼び。React Query 真実源・Zustandコピー禁止には抵触しない
- **レート制限/濫用対策**: 外部AIから叩かれる入口なので最低限のスロットリング
