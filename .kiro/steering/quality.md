# Quality Model — AI時代の品質モデル

AIでコードを書く時代に、**スピードと品質を両立**するためのこのプロジェクトの基本思想。
新機能・修正に関わる全エージェント（と人間）はこのモデルに従う。

## 前提：スピードと品質はトレードオフではない

遅さの正体は「手戻り」。バグを後で直すのが一番遅い。
よって **品質を上げること＝結果的にスピードを上げること**（手戻りが消えるから）。
目標は「速さと品質の両立」ではなく「**品質で速さを買う**」。

## 4つの品質モヤモヤと、その根っこ

AI時代の品質不安は、見た目は別物でも根っこは1つ：

> **「正しさの定義」がコードの外に・先に・存在しない**

| モヤモヤ               | 正体                                     |
| ---------------------- | ---------------------------------------- |
| マージ時の不安         | 正しいか判断する基準がない               |
| 意図が消える           | なぜそうしたかを記録していない           |
| テストが形骸化         | 何を守るテストか決めていない             |
| レビューが追いつかない | 機械が判定する基準がなく人間が全部抱える |

処方箋は1つ：**正しさを、コードの外に、先に、書く。**

## 役割分担モデル（人間とAIの境界）

| 段階           | 担当           | 内容                             | 殺すモヤモヤ         |
| -------------- | -------------- | -------------------------------- | -------------------- |
| ① 意図を書く   | **人間**       | 何を・なぜ作るか（requirements） | 意図が消える         |
| ② 正しさを書く | **人間が承認** | テスト(RED)＝仕様の機械化        | テスト形骸化         |
| ③ 実装する     | **AI**         | GREEN にする                     | （スピード担当）     |
| ④ 攻める       | **AIレビュー** | 壊れシナリオで敵対レビュー       | マージ不安           |
| ⑤ 決める       | **人間**       | アーキ整合・妥当性を判断         | レビュー追いつかない |

**人間が握るのは「意図」と「正しさの承認」だけ。** 実装とレビューの前さばきはAI。
これで人間の認知負荷が「全部」から「本質だけ」に減る。

### 重要な不変則

- **テスト（＝仕様の意図）の承認は人間が握る。** AIに実装とテストを同時に丸投げすると、テストが実装に合わせて書かれる「自作自演」が起き、コードとテストが同じ勘違いを共有する。最低でも RED のテストは人間がレビューして「これが正しさだ」と承認する。
- このモデルの ①②③⑤ は cc-sdd ワークフロー（`/kiro:spec-*`）が担う。

## AIレビューは「良い警官・悪い警官」の2体制

AIレビューは放っておくと「動いてるコードを否定しづらい」LGTM寄りになる。
そこで役割を **2体のエージェントに分離**（1体に褒めと攻めを同居させると両方薄まるため）：

|          | 😇 良い警官 `code-reviewer`     | 😈 悪い警官 `adversarial-reviewer` |
| -------- | ------------------------------- | ---------------------------------- |
| 守るもの | 健全さ（規約・既知パターン）    | 健全さ（壊れ方・攻撃耐性）         |
| やること | CLAUDE.md / steering 準拠の照合 | 本番で壊れるシナリオを暴く         |
| 性格     | 決定的・淡々・褒めない          | 敵対的・忖度しない・LGTM禁止       |
| 判定     | ❌1つで NEEDS-FIX               | Critical 1つで BLOCK               |

- **起動は並列**（独立した視点を混ぜない）。手動コマンド `/review` で起動する。
- **役割は基本分離＋セキュリティ/認可だけ意図的に両者に被せる**（致命領域は二重に見る）。
  - 「二重に見る」とは**両者ともチェックの中身まで読む**こと。良い警官は「`checkOwnership` が付いているか」だけで終わらせず比較演算子・例外処理まで確認し、悪い警官は呼び出しを見つけても「経路は塞がれた」と早合点せず迂回路と握り潰しを探す。「相手がやるだろう」で両者とも浅瀬しか見ない死角を作らない。
- **平均スコアは禁止**（致命傷1件が良さ4件で薄まるのを防ぐ）。最悪値で判定する。
- **最終判定（マージ可否）は人間が裁判官**として下す。AIは前さばきと論点整理まで。
