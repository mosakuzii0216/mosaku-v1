# Implementation Plan

> 削除専用スペック。設計の作業順序（コードとテストから onboarding 参照を全除去 → schema フィールド削除 → migration 生成と generate → 型チェック/テスト/lint）を固定する。Task 1（フロント）と Task 2（バックエンドモジュール）はレイヤー境界が分離しており並列実行可能。Task 3（schema migration）は Task 1・2 で参照が消えていることを前提とし、Task 4 が全体の健全性ゲート。

- [x] 1. フロントエンドのオンボーディング除去
- [x] 1.1 (P) オンボーディング UI コンポーネントと App.tsx 参照を削除する
  - 登録・初回ログイン直後にオンボーディングモーダルが表示されないようにし、Gate による起動判定そのものを撤廃する
  - オンボーディング UI コンポーネント群（Gate / Modal / ThemeGallery / ThemePreviewCard とその対応テスト）をディレクトリごと削除する
  - App.tsx からオンボーディング関連の import と JSX 参照を除去し、周辺レイアウト構造は維持する
  - 削除後にアプリ内へオンボーディング由来の分岐レンダリングが残らないことを確認する
  - _Requirements: 1.1, 1.2, 1.3, 1.4_

- [x] 1.2 (P) フロントエンドのデータ層・型・API クライアントを除去する
  - オンボーディング用の状態ストアとクエリフック（対応テスト含む）を削除する
  - API クライアントからオンボーディング完了・スキップ呼び出し関数を削除する
  - ユーザープロフィール型からオンボーディング完了フィールドを削除する
  - オンボーディングモジュール・関数・型への残存参照があれば型チェックがエラーを報告する状態（残存参照ゼロ）に保つ
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5_

- [x] 1.3 フロントエンドの取りこぼしテストを削除する
  - API クライアントテストからオンボーディング完了・スキップに関するケースを削除する
  - オンボーディング UI・クエリ・ストアのテストファイルをファイルごと削除する
  - フロントエンドのテストスイートがオンボーディング削除起因の失敗を出さないことを確認する
  - _Requirements: 5.3, 5.4_

- [x] 2. バックエンドのオンボーディングモジュール除去
- [x] 2.1 (P) OnboardingModule とエンドポイントを除去する
  - オンボーディングモジュール（controller / service / module / dto / spec）をディレクトリごと削除する
  - アプリケーションモジュールからオンボーディングモジュールの import と登録を除去する
  - 旧エンドポイント（オンボーディング完了・スキップ）が未登録となり 404 を返すようにする
  - auth / memo / theme / notebook の既存エンドポイントを変更せず維持する
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5_

- [x] 2.2 (P) 認証コントローラの getMe テストからオンボーディング依存を除去する
  - オンボーディング完了フラグの返却を前提とする getMe テスト群を該当テストごと削除する
  - findUserById 呼び出しを検証するテストはモック値のオンボーディング完了フィールドのみ除去して本体を残す
  - バックエンドのテストスイートが緑であることを確認する
  - _Requirements: 5.3, 5.4_

- [x] 3. データベーススキーマからオンボーディング完了カラムを削除する
  - Prisma スキーマの User モデルからオンボーディング完了フィールドを削除する
  - forward migration を新規生成し、当該カラムを DROP する SQL が記録されることを確認する
  - 既存の add カラム migration は履歴として編集しない
  - Prisma クライアントを再生成し、認証済みユーザー型と GET /auth/me レスポンスから当該フィールドが自動除外されることを保証する（手動型編集は不要）
  - 本番は新リビジョン切替後に migrate deploy を適用する順序を維持する（後方互換ウィンドウ回避）
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 5.6_

- [x] 4. 全体の健全性ゲートと保護境界の確認
  - フロントエンド・バックエンド両方のビルドと型チェックがエラーなく完了することを確認する
  - lint が未使用 import・未参照シンボルに関する新規エラーを出さないことを確認する
  - 既存のユニット・E2E テストがオンボーディング削除起因の失敗を出さないことを確認する
  - メール送信元デフォルト値（onboarding@resend.dev とその参照テスト）が無変更であることを差分で確認する
  - テーマ選択導線がノートブックエディタのテーマドロップダウン経由で引き続き機能することを確認する
  - _Requirements: 1.5, 2.5, 5.1, 5.2, 5.3, 5.5_
