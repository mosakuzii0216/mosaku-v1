# Implementation Plan

## invitation-manager-api-client

---

- [ ] 1. 非 OK レスポンスからサーバーエラーメッセージを取り出せるようにする
  - 非 OK レスポンスで Content-Type が JSON の場合、レスポンスボディからエラーメッセージを取り出す処理を追加する
  - JSON パース失敗時は `HTTP error! status: N` 形式のフォールバックメッセージを使用する
  - 既存の 401 認証エラーハンドリングは変更しない
  - この強化により、公開エンドポイント向けヘルパーや任意認証ヘルパー経由の全 API 呼び出しにも自動的に適用されることを確認する
  - _Requirements: 1.2, 3.6_

---

- [ ] 2. 招待コード検証を内部ヘルパー経由に切り替える
  - 招待コード検証が生の fetch を直接呼ぶ代わりに、内部の公開エンドポイント向けヘルパーを使用するよう書き換える
  - タスク 1 で強化したエラー処理が招待コード検証にも適用されることを確認する
  - メソッドのシグネチャと戻り値の型は変更しない
  - API クライアントクラス内に中央 HTTP ヘルパー以外の fetch 直呼び出しが残っていないことを確認する
  - _Requirements: 1.1, 1.3, 3.4, 3.5, 4.2_

---

- [ ] 3. AuthAPI の全 API 呼び出しを内部ヘルパー経由に統一する
- [ ] 3.1 (P) 認証前フロー（ログイン・登録・パスワードリセット）を内部ヘルパー経由に移行する
  - ログイン・登録・パスワードリセットの各メソッドで生の fetch の代わりに内部の通信ヘルパーを使用するよう書き換える
  - ログイン成功後にアクセストークンを保存する処理は維持する
  - 各メソッドのデフォルトエラーメッセージ文言は変更しない
  - メソッドのシグネチャ（引数・戻り値型）は変更しない
  - _Requirements: 2.1, 2.2, 2.3, 3.1, 3.3, 3.4_

- [ ] 3.2 OAuth 招待登録フロー（5 メソッド）を内部ヘルパー経由に移行する
  - Google・GitHub・LINE・Apple・X の各 OAuth 招待登録メソッドで生の fetch の代わりに内部の通信ヘルパーを使用するよう書き換える
  - 各登録成功後にアクセストークンを保存する処理は維持する
  - Apple 登録のオプション引数を含む各メソッドのシグネチャは変更しない
  - 各メソッドのデフォルトエラーメッセージ文言は変更しない
  - 認証 API クラス内に通信ヘルパー以外の fetch 直呼び出しが残っていないことを確認する
  - _Requirements: 2.4, 2.5, 2.6, 2.7, 2.8, 2.9, 3.2, 3.3, 3.4, 4.3_

---

- [ ] 4. fetch 直呼び出し排除の完全性を検証し、テストを書く
- [ ] 4.1 アプリケーションコードに残存する fetch 直呼び出しがないことを確認する
  - フロントエンドのアプリケーションコードを検索し、許可された箇所以外に fetch の直呼び出しがないことを確認する
  - API クライアントは中央 HTTP ヘルパー内のみ、認証 API は内部通信ヘルパー内のみに fetch があることを確認する
  - テーマ CSS 読み込みに使われる fetch は静的アセット取得として例外扱いであることを確認する
  - _Requirements: 4.1, 4.4_

- [ ] 4.2 エラー抽出と招待コード検証の動作を確認するテストを書く
  - JSON レスポンスを持つ非 OK レスポンスからサーバーのエラーメッセージを取り出せることをテストする
  - JSON パース失敗時に `HTTP error! status: N` 形式にフォールバックすることをテストする
  - 招待コード検証が成功時に正しいレスポンス型を返すことをテストする
  - 招待コード検証が非 OK 時にサーバーのメッセージを含む Error をスローすることをテストする
  - _Requirements: 1.2, 3.5, 3.6_

- [ ]\* 4.3 AuthAPI メソッドの動作確認テストを書く
  - ログインが成功時にアクセストークンを保存することをテストする
  - Google OAuth 招待登録が成功時にアクセストークンを保存することをテストする
  - 非 OK レスポンス時に各メソッドが適切な Error をスローすることをテストする
  - メソッドのシグネチャが変更されていないことを TypeScript 型チェックで確認する
  - _Requirements: 2.1, 2.4, 3.1, 3.2, 3.3, 3.4_
