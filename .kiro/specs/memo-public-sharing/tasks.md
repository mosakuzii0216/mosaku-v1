# Implementation Plan

> 設計の Migration Strategy（Phase 0 → 4）に沿って構成。バックエンド先行 → フロント閲覧ビュー → 所有者向け UI → 観測性・E2E 検証の順に進行する。
> 並列マーカー `(P)` は、同フェーズ内で別ファイル群かつ依存のない作業に付与している。

## Phase 0 — Data Schema

- [x] 1. メモ公開メタデータをデータモデルに追加する
  - `memos` レコードに公開トークンと公開日時を保持できるようにし、公開メタデータの一意性を DB レベルで担保する
  - 公開トークンに UNIQUE 制約、`(user_id, published_at DESC)` 複合インデックスを追加し所有者向け一覧クエリを最適化する
  - 既存メモはすべて非公開状態として扱えるようバックフィル不要のマイグレーションにする
  - Prisma クライアントを再生成し、型レベルで公開メタデータが扱えるようにする
  - _Requirements: 1.1, 1.2, 2.5_

## Phase 1 — Backend Services & Controllers

- [x] 2. メモ公開ライフサイクルを管理するサービス層を実装する
- [x] 2.1 推測困難な公開トークンを生成し衝突を回避する仕組みを実装する
  - 128bit 以上のエントロピー（実装上は 256bit）を持つ URL セーフトークンを暗号論的乱数から生成する
  - 識別情報やメモ ID を平文で含めないこと、生成ロジックがメモ ID / ユーザー ID を入力に取らないことを担保する
  - DB の UNIQUE 制約違反（P2002）を捕捉して最大 5 回再生成リトライし、枯渇時は 5xx として例外を Sentry に送出する
  - _Requirements: 2.1, 2.3, 2.4_
- [x] 2.2 メモを公開・非公開に切り替えるユースケースを実装する
  - 所有権検証を共通の認可サービス経由で実施し、所有者以外の操作は認可エラーにする
  - ゴミ箱に入っているメモへの公開操作を 404 として拒否し、ゴミ箱内メモは公開対象から確実に除外する
  - 公開操作で新規トークンと公開日時を保存し、非公開操作で公開トークンと公開日時を NULL に戻す
  - 公開→非公開の状態遷移後は公開 URL からの一切のアクセスが 404 になることを境界条件として確認する
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5_
- [x] 2.3 公開中メモのトークン再生成ユースケースを実装する
  - 旧トークンを即時無効化し新トークンを保存する単一操作にする（旧トークンと新トークンが同時に有効な瞬間を作らない）
  - 衝突回避ロジック（2.1）を再利用し、再生成時の衝突も同じ最大 5 回リトライで処理する
  - 再生成時に公開日時も更新する（公開期間の起点をリフレッシュする扱い）
  - _Requirements: 2.2, 2.3_
- [x] 2.4 所有者の公開中メモ一覧を返すユースケースを実装する
  - 自分が所有する公開中メモを公開日時の降順で返す
  - レスポンスにメモ ID / タイトル / 公開トークン / 公開日時 / 最終更新日時を含める（個人情報は含めない）
  - _Requirements: 5.1_
- [x] 2.5 公開トークンから閲覧者向けビューを解決するユースケースを実装する
  - 公開中かつゴミ箱外のメモを抽出し、タイトル / 本文 / 最終更新日時のみを返す
  - 存在しない・無効化された・ゴミ箱内のいずれも 404 として区別不能に統一する
  - 所有者識別情報・OAuth プロバイダ・ロール・ノートブック ID・タグなど個人/コンテキスト情報を一切含めない
  - _Requirements: 3.1, 3.2, 3.3_
- [x] 2.6 公開状態遷移の監査ログを構造化送信する
  - 公開・非公開・トークン再生成の各イベントを `feature_area: 'memo'` タグ付きで送信し、payload にメモ ID と理由（手動/カスケード）を含める
  - 例外時は既存の Sentry グローバルフィルタに任せ、本機能専用の例外ハンドラは追加しない
  - _Requirements: 6.1, 6.4_
- [x] 2.7 メモ公開サービスの単体テストを整備する
  - 公開化・非公開化・再生成・一覧・トークン解決の正常系を網羅する
  - ゴミ箱内メモへの公開で 404 が返ること、`findByToken` のレスポンスに個人情報が含まれないことを assertion レベルで確認する
  - トークン衝突リトライが指定回数で打ち切られることを検証する
  - _Requirements: 1.5, 2.3, 3.2_

- [x] 3. 所有者向け公開系 API エンドポイントを追加する
- [x] 3.1 メモ公開・非公開・再生成・一覧の 4 エンドポイントを実装する
  - 既存のメモ Controller 配下に、公開化（POST）/ 公開解除（DELETE）/ 再生成（POST）/ 自分の公開中メモ一覧（GET）を追加する
  - 全てグローバル JWT 認証配下に置き、サービス層が所有権検証を必ず行う構造にする
  - 公開化と再生成のレスポンスはメモ ID / 公開トークン / 公開日時を、一覧レスポンスは加えて最終更新日時とタイトルを返す
  - _Requirements: 1.1, 1.2, 1.4, 2.2, 5.1, 5.3_
- [x] 3.2 (P) 所有者向け API の e2e テストで認可と状態遷移を検証する
  - 所有者でないユーザーからのリクエストが 403 になることを確認する
  - 公開→非公開→再公開→再生成のライフサイクルが期待どおりに状態を変えることを確認する
  - 公開メモ一覧が公開日時の降順で返り、レスポンス DTO に個人情報が含まれないことを確認する
  - _Requirements: 1.4, 2.2, 5.1, 5.3_

- [x] 4. 未ログイン閲覧用の公開メモ API を追加する
- [x] 4.1 公開トークン解決エンドポイントを未認証で公開する
  - 公開メモ閲覧エンドポイントをグローバル JWT Guard の対象外（`@Public()`）にして、未ログインでアクセス可能にする
  - レート制限デコレータで IP 単位の制限を適用し、未ログインの過剰アクセスから所有者のメモを保護する
  - レスポンスヘッダーに短時間の Cache-Control（`private, max-age=30, must-revalidate`）を付与し、解除直後の閲覧者が長くキャッシュを掴み続けないようにする
  - パスパラメータの公開トークンを URL セーフ文字列としてバリデーションする（長さ・文字種チェック）
  - _Requirements: 3.1, 3.4, 3.5, 3.6, 4.1, 6.3_
- [x] 4.2 リバースプロキシ配下で正しい接続元 IP を解決できるよう設定する
  - アプリケーション起動時に `trust proxy` を有効化し、レート制限と既存 IP ベース機能が GCLB / Cloud Run 配下で正しく動作するようにする
  - 既存の認証スロットルなど IP に依存する箇所への副作用がないことを確認する
  - _Requirements: 3.6_
- [x] 4.3 (P) 公開メモ閲覧 API の e2e テストを整備する
  - 未認証で 200 を返すこと、存在しない / 無効化済み / ゴミ箱内の各ケースで一律 404 を返すことを確認する
  - レスポンスに想定どおりの Cache-Control ヘッダーが付与されることを確認する
  - レスポンス本体に個人情報（email / userId / notebookId 等）が含まれないことを assertion する
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.6, 6.3_

- [x] 5. ゴミ箱遷移時に公開状態を自動解除するカスケード処理を追加する
  - メモのゴミ箱遷移ハンドラから公開解除ユースケースを呼び出し、公開中メモがゴミ箱に入ったら自動で非公開化する
  - 既に非公開なら no-op で扱い、監査ログには理由として `cascade-trash` を記録する
  - 循環参照を避けるため、公開サービスはメモ本体サービスを参照しない一方向依存にする
  - 公開中メモを trash した時に公開トークンが NULL 化されるユニットテストを追加する
  - _Requirements: 1.6, 6.1_

## Phase 2 — Frontend Data Layer & Public Viewer

- [x] 6. フロントエンドの公開系データアクセス層を実装する
- [x] 6.1 公開系 API を呼び出すクライアントメソッドを `apiClient` に追加する
  - 所有者向け 4 操作（公開 / 解除 / 再生成 / 自分の公開メモ一覧）を認証付きリクエストで実装する
  - 未ログイン閲覧用の公開メモ取得は `requestPublic` 経由で実装し、認証ヘッダーを付与しない
  - 直接 `fetch` を呼ばず、必ず共通クライアント経由で実装する（プロジェクト不変則）
  - _Requirements: 1.1, 1.2, 2.2, 3.1, 5.1_
- [x] 6.2 公開系クエリキー階層と React Query フック群を実装する
  - `queryKeys.memos` を拡張し、自分の公開中メモ一覧と公開トークン解決ビューの 2 つのキーを追加する
  - 公開・非公開・再生成のミューテーション成功時に該当メモ詳細・メモ一覧・自分の公開中メモ一覧のキャッシュを無効化する
  - 再生成時は旧トークンの閲覧クエリキャッシュを明示的に除去する
  - 未ログイン閲覧クエリは 404 即時失敗（リトライ無効）+ 短い staleTime / gcTime を設定する
  - React Query を真実の源泉として扱い、Zustand へのコピーは行わない（プロジェクト不変則）
  - _Requirements: 6.2_

- [x] 7. 未ログイン閲覧者向けの公開メモ閲覧ビューを構築する
- [x] 7.1 公開トークン URL のルートを AuthGuard 外に追加する
  - `/p/:token` をルーターに登録し、ログイン状態に関わらず同一の閲覧専用ビューが描画されるようにする
  - ログイン済みユーザーが踏んだ場合もアプリ内認証フローへリダイレクトせず、閲覧専用ビューを返す
  - _Requirements: 3.5_
- [x] 7.2 (P) 公開メモのルートコンポーネントとローディング / 404 ハンドリングを実装する
  - URL から公開トークンを取り出し、公開メモ取得クエリの結果に応じてローディング / 成功 / 404 表示を切り替える
  - 404 時は「メモが存在しないか公開が解除されています」のような中立的なメッセージと、Mosaku トップへの導線を表示する
  - ブラウザタブのタイトルをメモタイトル + サービス名で動的更新する
  - _Requirements: 3.1, 3.3, 3.5_
- [x] 7.3 (P) TipTap ベースの読み取り専用本文レンダラを実装する
  - 編集機能・toolbar・Mention 拡張・onChange を持たない読み取り専用エディタとして初期化する
  - 既存 RichTextEditor のスキーマと整合する StarterKit のみのレンダリングにする
  - _Requirements: 4.3_
- [x] 7.4 (P) 公開閲覧ビュー本体に閲覧専用 UI とサービス CTA を実装する
  - タイトル・本文レンダラ・最終更新日時を表示し、編集 UI / コメント入力欄 / 複製ボタンを一切持たない
  - 「これは閲覧専用の公開メモです」「Mosaku は招待制のメモアプリです」というメッセージと招待ページへの導線を画面下部に表示する
  - _Requirements: 3.1, 3.2, 4.1, 4.3, 4.4_

## Phase 3 — Owner Integration UI

- [x] 8. メモエディタヘッダーから公開操作を行えるようにする
- [x] 8.1 公開状態の切り替えと共有メニューを提供するコントロールを実装する
  - 非公開時は「公開する」ボタン、公開中は公開バッジと共有メニュー（URL コピー / トークン再生成 / 公開解除）を提示する
  - 公開 URL はクライアント側でアプリオリジン + `/p/{token}` の形に組み立て、クリップボードにコピーできるようにする
  - 各操作後はトーストでフィードバックし、確実にキャッシュ無効化が連動するように 6.2 のフックを利用する
  - _Requirements: 5.2, 5.3, 5.5_
- [x] 8.2 メモエディタ画面にコントロールを統合する
  - エディタヘッダーの目立つ位置に公開コントロールを配置し、所有者がメモ編集中にそのまま公開状態を確認・変更できるようにする
  - メモがゴミ箱内のときはコントロールを無効化（操作不可）として表示する
  - _Requirements: 1.5, 5.5_

- [x] 9. 公開メモ管理ダッシュボードを設定ページに追加する
- [x] 9.1 (P) 公開メモ一覧カードと各種アクションを実装する
  - 自分の公開中メモを公開日時の降順で一覧表示し、各エントリで URL コピー / トークン再生成 / 公開解除を提供する
  - 0 件のときは「現在公開中のメモはありません」とメモ編集画面からの公開導線説明を表示する
  - 各操作後は一覧キャッシュとメモ詳細キャッシュが連動して更新されることを確認する
  - _Requirements: 5.1, 5.2, 5.3, 5.4_
- [x] 9.2 設定ページに公開メモ管理カードを配置する
  - 既存の設定セクション構成と整合する位置にカードを追加し、ユーザーが公開状態の棚卸しに迷わずアクセスできるようにする
  - _Requirements: 5.1_

- [x] 10. 所有者向け UI のコンポーネントテストを整備する
- [x] 10.1\* (P) 公開閲覧ビューと所有者向けコントロールのレンダリングテストを追加する
  - 公開閲覧ビューに編集 UI・コメント欄・複製ボタンが存在しないこと、CTA が表示されることを確認する
  - 公開コントロールが非公開状態と公開状態で適切な操作群を出し分けることを確認する
  - 公開メモ管理カードが空状態と一覧状態で適切な表示を行うことを確認する
  - _Requirements: 4.3, 4.4, 5.2, 5.4_

## Phase 4 — Verification & Observability

- [x] 11. 公開機能のエンドツーエンドシナリオを Playwright で検証する
  - 所有者がメモを公開した直後に、別ブラウザコンテキスト（未ログイン）で公開 URL を開いて閲覧できることを確認する
  - 所有者が公開解除した直後に同じ URL が 404 表示になることを確認する
  - 公開閲覧ビューに編集 UI / コメント入力欄 / 複製ボタンが存在せず、サインアップ導線 CTA が表示されることを確認する
  - _Requirements: 1.2, 1.3, 3.1, 3.3, 4.3, 4.4_

- [ ] 12. パフォーマンスと監視の運用受け入れを確認する
  - 公開中メモ一覧クエリで `(user_id, published_at DESC)` 複合インデックスが利用されることを EXPLAIN で確認する
  - 公開・非公開・再生成イベントが Sentry の `feature_area: 'memo'` フィルタで取得可能であることを確認する
  - 公開閲覧 API の Cache-Control / Vary レスポンスヘッダーが本番ビルドで意図どおり付与されていることをスモーク確認する
  - _Requirements: 6.1, 6.2, 6.3, 6.4_
