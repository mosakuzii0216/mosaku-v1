# Implementation Plan

## editor-surface-tokenization

> 本 spec は theme-immersive-world で確立した Layer①（トークン＋質感プリミティブ）を**エディタ面へ縦展開**する。依存の向きは **語彙（Task 1）→ プリミティブ（Task 2）→ 源泉一本化・本文ブリッジ（Task 3・4）→ コンポーネント置換（Task 5・6）→ 統合検証（Task 7）** で固定し、この順を守ることで各段階が独立して緑を保てる。
>
> 全タスクの不変則: 色は必ずトークン参照経由でコンポーネントに直書きしない／面ごとの専用クラスを新設しない／テーマ名をコード側に書かない／要素型セレクタで汎用 HTML の文字色を上書きしない（過去のヘッダー文字消失の再発防止）／外部 JS ライブラリ追加ゼロ／バックエンド・DB スキーマ不変。**置換するのは配色・状態表現・面の質感だけで、レイアウト系ユーティリティ・DOM 構造・イベントハンドラ・props は温存する。**
>
> 値の実装は中立既定と森（mori）に限定し、海・夜・朝は placeholder のまま残す。後続の横展開 spec が値を与えるだけで4テーマへ波及する構造を保つ。
>
> **スコープ外（既知の残件）**: 本文面のタイポグラフィ定義は Layer③ のテーマ CSS に残す。構文ハイライトの配色（トークン種別ごとに10色超の独立語彙を要する）は後続 spec へ送り、森でコードブロックだけ配色が浮くことを既知の劣化として受け入れる。

- [x] 2. 質感プリミティブの拡張（Layer① 構造クラス）

- [x] 2.1 押下・ホバー・無効の状態表現をボタンプリミティブへ追加する
  - トグル操作要素の押下（ON）状態を、テーマ名を含まない theme-neutral な質感プリミティブとして質感層へ備える

  - ホバーは非押下時のみ効かせ、押下中のホバーで ON 表現が壊れないようにする
  - 無効状態は**不透明度を使わず前景色の切替**で表現する（半透明の面に不透明度を重ねると生きた背景の最明値が二重に透けて実効コントラストが崩壊するため）。あわせて操作不可のカーソルを与える
  - 色は全てトークン参照のみで構成し、生のカラーリテラルとテーマ名を持たせない
  - Task 1 の語彙に依存するため Task 1 完了後に着手する

  - 候補行にホバー・選択・フォーカスの状態表現を与え、選択中が非選択と判別可能なコントラストを保つようにする

  - 2.1 と同一ファイルを拡張するため 2.1 完了後に実施する

- [x] 2.3 プリミティブの構造契約と Layer① の軽量性を機械検証する
  - 新クラス・新状態の存在と、それぞれが読むトークンを検証する
  - 無効状態が不透明度を使わないこと、浮遊面プリミティブが高さ制約・スクロール・寸法を宣言しないことを機械検証し、面の質感とレイアウトの分離を構造的に固定する
  - 新クラスが reduced-motion ブロックに列挙され、モーション停止時も配色・奥行き・余白の静的な質感が維持されることを検証する

  - フロントエンドの依存に新規追加が無いことを固定する
  - 既存の「リテラル禁止」「トップレベルセレクタ制限」検査が新クラス追加後も通過することを確認する
