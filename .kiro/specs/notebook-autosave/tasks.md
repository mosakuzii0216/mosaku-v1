# Implementation Plan

> 並列実行について: 本機能の実装はほぼ単一ファイル（`NotebookEditor.tsx`）への逐次的な拡張と、その共有依存（presentation モジュール）・単一のテストファイルに集約される。各タスクは前タスクの出力（共有モジュール／純保存関数／配線）に依存するか、同一ファイルを編集するため `(P)` 並列マーカーは付与しない。

- [x] 1. 保存状態表示を両エディタ共有モジュールへ移設（Migration ①）
- [x] 1.1 保存状態表示ロジックを editor 中立モジュールへ抽出
  - メモ専用名前空間にある保存状態の文言・トーン（色クラス）・相対時刻フォーマットを、メモ非依存の中立モジュールへ移設する
  - 状態種別ごとの文言判定（保存中／保存済み／エラー）と網羅チェック、相対時刻の整形、トーン→CSS クラスの対応表を単一ソースとして export する
  - ロジック本体は不変とし、メモの保存体験を変えない
  - _Requirements: 2.5_

- [x] 1.2 MemoEditor の参照を共有モジュールへ付け替え回帰確認
  - MemoEditor とメモ専用ユーティリティの import を新しい共有モジュールへ向け替え、旧名前空間の重複 export を除去する
  - 既存のメモ保存状態テストが緑のままであることを移設の挙動不変の判定基準とする
  - _Requirements: 2.5_

- [x] 2. NotebookEditor の自動保存コア配線（Migration ②）
- [x] 2.1 純保存関数の実装（遷移副作用の分離）
  - ノートブック保存を apiClient 経由の React Query mutation に委譲する純保存関数を実装し、保存成功時の一覧遷移副作用を取り除く
  - フォーム値（名前・本文・テーマ）を保存ペイロードへ正規化し、テーマ未選択センチネルは null へ変換する
  - 名前と本文がともに空（trim 後）の場合は保存を実行しない
  - 明示的な編集完了／キャンセル操作（「閉じる」）でのみ一覧へ遷移する経路を残す
  - サーバー状態は React Query を真実の源泉とし、保存対象データを Zustand へコピーしない
  - _Requirements: 1.3, 1.4, 1.6, 4.1, 4.2, 5.4_

- [x] 2.2 useAutoSave 配線と debounce トリガー
  - 名前・本文の変更で debounce タイマーを開始し保存状態を保存待ちへ遷移、追加変更でタイマーをリセットして最後の変更から待機後 1 回だけ保存する
  - 保存処理が進行中のときは新たな自動保存実行を抑止し保存待ちを維持する
  - 純保存関数を debounce のコールバックとして結線し、空保存・保存中の抑止はタイマー発火時に一元評価する
  - _Requirements: 1.1, 1.2, 1.5_

- [x] 2.3 新規作成の自動保存と編集モード内部遷移
  - 新規作成中に名前または本文が非空で debounce が発火したらノートブックを 1 件作成する
  - 作成成功時に detail キャッシュへ作成結果を seed し、以降の保存が同一ノートブックの更新になるよう編集モードへ内部遷移する
  - 編集モード遷移後も一覧へは遷移せず、直近の入力を保持したまま編集を継続できる状態を維持する
  - _Requirements: 5.1, 5.2, 5.3_

- [x] 2.4 編集対象切替の再同期 ref ガード
  - 編集対象のノートブックが切り替わったら進行中の debounce をキャンセルし、新対象の名前・本文・テーマ・タグ・最終保存時刻でフォーム状態を再同期する
  - 再同期を id 単位 1 回 + データ到着待ちの命令的ガードで行い、同一ノートブックの再フェッチ（参照のみの変化）では再同期せず直近の入力を保持する
  - 新規作成への切替時はフォームを初期化しガードをセンチネルへ設定する
  - _Requirements: 4.3, 8.1, 8.2, 8.3_

- [x] 3. 保存状態インジケーターと明示保存
- [x] 3.1 保存状態インジケーターの表示
  - 自動保存・明示保存の進行中は「保存中」、成功時は「保存済み」と最終保存時刻からの相対時刻を併記し、共有モジュールの文言・トーン・相対時刻フォーマットでメモと一貫させる
  - 既存ノート編集中で保存状態が idle（初期表示／全変更巻き戻し）のときは「保存済み」を表示し、新規作成中でまだ保存対象が未確定のときはインジケーターを表示しない
  - 最終保存時刻設定後はメモと同じ 30 秒間隔で相対時刻表示を更新する
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.6_

- [x] 3.2 明示保存（ボタン・キーボードショートカット）の併存
  - 自動保存導入後も明示保存ボタンを保持し、変更が存在しない／保存処理が進行中のときは非活性にする
  - Ctrl+S / Cmd+S でブラウザ既定動作を抑止し、進行中の debounce をキャンセルして即時保存を実行する
  - 明示保存実行時に debounce タイマーをキャンセルして自動保存との二重保存を防止し、成功時は自動保存と同一の保存状態インジケーター更新を行う
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5_

- [x] 4. テーマ・タグの自動保存とエラー処理
- [x] 4.1 テーマ・タグ変更の自動保存対象化
  - テーマ変更を保存ペイロードへ含め、テーマ・タグの変更を自動保存のトリガーとして扱う（タグ差分検知の基準を保持し変更を検出する）
  - ノートブック本体の保存成功後にタグ割り当て反映 API を実行する
  - タグ反映 API が失敗しても本体保存結果を破棄せず、エラーをログに記録する
  - _Requirements: 6.1, 6.2, 6.3, 6.4_

- [x] 4.2 保存失敗時のエラー提示・入力保持・再試行
  - 自動保存・明示保存がサーバーエラーで失敗したら保存状態を「エラー」として提示する
  - 保存失敗時もユーザーの入力（名前・本文・テーマ・選択タグ）を保持し破棄せず、再フェッチによる上書きは再同期ガードで防止する
  - 失敗後の再編集で改めて自動保存を試行する
  - _Requirements: 7.1, 7.2, 7.3_

- [x] 5. テスト（Migration ③）
- [x] 5.1 自動保存コアのユニットテスト
  - 名前・本文変更で debounce 後に apiClient 経由保存が 1 回だけ走ること、ともに空では保存しないことを検証する
  - 自動保存成功で一覧へ遷移しないこと、新規作成の自動保存成功で detail キャッシュ seed と編集モード遷移が走り入力が保持されることを検証する
  - 同一ノートの再フェッチ（参照変化）でフォーム状態が再同期されないことを検証する
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 4.1, 4.3, 5.1, 5.2, 5.3, 8.3_

- [x] 5.2 切替再同期・テーマ/タグ反映の統合テスト
  - 別ノートへの切替で debounce がキャンセルされ新対象で再同期され、前ノートの入力・タイマーが混入しないことを検証する
  - テーマ・タグ変更が自動保存をトリガーし本体保存後にタグ反映 API が実行されること、タグ反映失敗時に本体保存結果が破棄されずログのみとなることを検証する
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 8.1, 8.2_

- [x]\* 5.3 明示保存・インジケーターの UI テスト
  - 明示保存ボタンの非活性条件（変更なし／保存中）と Ctrl/Cmd+S での即時保存・二重保存防止を検証する
  - 保存状態インジケーターの遷移（保存中→保存済み＋相対時刻、既存ノート idle→保存済み、新規作成中は非表示）がメモと一貫することを検証する
  - 既存のメモ保存状態テストが緑のまま（表示ロジック移設の挙動不変）であることを確認する
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 3.2, 3.3, 3.4_
