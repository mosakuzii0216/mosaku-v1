# Implementation Plan

> 既存資産メモ: `normalizeRoute` / 5 タグ契約（G1）と `memo-sharing.dependency.spec.ts`（G3）、`MemoSharingService.findByToken` は実装済み。本計画はそれらを契約として固定しつつ、残る観測発出源（薄い Interceptor 2 枚）と運用 runbook を新規に実装する。Stage 2/3 の物理分割は Non-Goal（Req 5.5）。

- [x] 1. 公開読み取り観測 Interceptor の実装
- [x] 1.1 公開読み取り用の横断観測 Interceptor を実装する
  - 公開読み取り完了時（成功・例外問わず）に、固定キー `public_memo_read` の構造化 JSON ログを 1 行発出する
  - `route` は既存の route 正規化ユーティリティ（`common/sentry`）を必ず通し、生トークンを payload に絶対に含めない不変条件を守る
  - `feature_area` を既存 enum の `memo` に固定し、`status` / `latency_ms` / `severity`（status>=500 で ERROR）を確定して発出する
  - タグ・ラベル欠落時は既存タグ契約を満たすフォールバック値を付与する
  - ログ発出失敗・正規化例外は握り潰し、リクエスト処理を中断させない（observability は correctness を妨げない）
  - _Requirements: 1.1, 1.3, 1.5, 6.3_
- [x] 1.2 Interceptor を公開コントローラにスコープ適用しモジュールへ登録する
  - 公開読み取りコントローラにのみコントローラスコープで適用し、編集経路には適用しない（発出源を物理的に分離）
  - メモモジュールの provider として登録し、グローバル登録はしない
  - _Requirements: 1.1, 1.3_
- [x] 1.3 公開観測 Interceptor のユニットテストを追加する
  - `route` が `:token` 正規化された値のみになることを固定する
  - 生トークンが payload に一切出ないことを固定する
  - 200 / 404 / 例外それぞれで 1 件発出され、`status` / `severity` / `latency_ms` が正しいことを検証する
  - _Requirements: 1.1, 1.3, 6.3_

- [x] 2. 編集経路の対称レイテンシ Interceptor の実装
  - 注意: 編集コントローラ登録のためタスク 1 と同一モジュール定義を編集する。タスク 1 完了後に着手する
- [x] 2.1 編集経路に対称な横断観測 Interceptor を実装・登録する
  - 編集コントローラスコープに公開側と同型の薄い Interceptor を適用し、固定キー `memo_edit_read` ＋正規化 route で `latency_ms` を発出する
  - 横断観測のみとし、既存ハンドラのロジック・`@Public()` opt-out・`AuthorizationService` 一元化には一切手を入れない
  - 公開側と編集側が共通の route 正規化ユーティリティ（下位共通レイヤー）のみを共有し、一方向 DI の継ぎ目を維持する
  - _Requirements: 2.4, 6.4_
- [x] 2.2 編集観測 Interceptor のユニットテストを追加する
  - 編集経路の route が正規化され、固定キー `memo_edit_read` で `latency_ms` が発出されることを固定する
  - 公開キー `public_memo_read` と混線しないことを検証する
  - _Requirements: 2.4_

- [x] 3. 公開データ境界とメトリクス分離の回帰固定
- [x] 3.1 (P) 公開メモ読み取りのデータ境界回帰テストを増強する
  - 未公開・ゴミ箱（soft delete）・無効トークンで 404（存在秘匿）になることを固定する
  - 公開メモで返却されるのは公開用フィールドのみで、内部 ID・所有者識別情報・編集系フィールドが露出しないことを固定する
  - _Requirements: 4.1, 4.2, 4.3_
- [x] 3.2 公開コントローラのアクセス境界を統合テストで検証する
  - `@Public()` により JWT なしでアクセス可、それ以外のメモエンドポイントはグローバル JWT Guard が維持されることを検証する
  - `Cache-Control: private, max-age=30, must-revalidate` ヘッダが維持されることを検証する
  - 公開経路が GET のみの読み取り専用で、編集・削除・所有権変更を許可せず認可バイパスを新設していないことを検証する
  - _Requirements: 3.5, 4.4, 4.5, 6.4_
- [x] 3.3 メトリクスログの公開／編集分離とレート算出を統合テストで検証する
  - 公開経路は `public_memo_read` のみを発出し、編集経路は別キーで発出してメトリクスフィルタ上で混線しないことを検証する
  - レート制限（IP 60req/分）超過で 429 が発火し、429 は Interceptor 到達分の公開カウントには現れず、Cloud Run ネイティブログ由来の throttled 計上として別経路で扱われる前提を固定する
  - 公開 req レートが served ＋ throttled の和で算出される契約をテストまたはアサーションで明示する
  - _Requirements: 1.1, 2.1_

- [x] 4. 一方向 DI 継ぎ目を CI で恒久検証する
  - 公開読み取り経路（共有サービス／公開コントローラ）が編集系サービスを import しないことをフィットネステストでアサートする
  - 逆方向依存を一時的に追加すると RED になることを設計前提として維持する
  - 共通で必要なロジックは双方が依存可能な下位共通レイヤーに配置し、編集系サービス経由の間接依存を作らない
  - 既存フィットネステストを正式な品質ゲートとして CI 実行対象に維持する
  - _Requirements: 3.1, 3.2, 3.3, 3.4_

- [x] 5. 運用 runbook（トリガー定義・メトリクス／アラート・段階分離 Playbook）
  - 注意: 5.1〜5.4 は単一の runbook ファイルを順に編集するため逐次実行する
- [x] 5.1 ログベースメトリクス定義の gcloud 断片を runbook に記載する
  - 公開読み取りの count（status_class ラベル）・latency 分布・429 throttled 補完メトリクスの定義断片を記載する
  - 編集経路の route 別レイテンシメトリクス定義断片を記載する（Req 2.4 の一次データ源）
  - 公開 req レート＝公開 count ＋ throttled の和で導出する旨を明記する
  - _Requirements: 1.3, 2.1_
- [x] 5.2 アラートポリシーの gcloud 断片を runbook に記載する
  - 公開 req レート／編集 p95 劣化／インスタンス使用率／DB プール使用率の各アラートを継続時間条件付きで定義する
  - 編集 p95 劣化と公開 req 上昇の相関を「編集体験への影響あり」として識別可能なアラートにする
  - _Requirements: 2.2, 2.4_
- [x] 5.3 数値トリガー定義表とトリガー→分離段階の対応表を記載する
  - 公開 req レート・DB コネクションプール使用率・編集系 p95 劣化・Cloud Run インスタンス使用率を閾値・継続時間付きで明文化する
  - 各トリガーが発動すべき段階的分離オプションへの対応関係を表で定義する
  - 通常運用（閾値未超過）では物理分割や読み取りレプリカ構築を自動でも手動でも要求しない原則を明記する
  - _Requirements: 2.1, 2.3, 2.5_
- [x] 5.4 段階的分離 Playbook を記載する
  - 3 段階（CDN 前段キャッシュ化 → Cloud Run 2 分割 → 読み取りレプリカ）を内容・前提トリガー・適用順序・依存関係込みで文書化する
  - 第1段の公開メモのキャッシュ可能性と、公開解除・更新時のキャッシュ無効化（鮮度）要件を明示する
  - 各段階のロールバック（退避）手順を定義する
  - 第2段・第3段の物理実装は本フェーズ成果物に含めない（Non-Goal）ことを明記する
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.5_

- [x] 6. 既存アーキテクチャ不変則の維持を検証する
- [x] 6.1 観測タグ・サンプリングの不変則を固定する
  - 5 タグ契約（environment / release / feature_area / route / user_facing）と `feature_area` enum が既存定義から逸脱しないことを固定する
  - 公開読み取りトレースが既存サンプリング戦略の枠内で取得され、コード変更でサンプリング率を変更しないことを確認する
  - _Requirements: 1.2, 1.4, 1.5, 6.3_
- [x] 6.2 フロント不変則と品質ゲートの通過を確認する
  - 公開メモ取得を含む全 API コールが `apiClient` 経由を維持し、直接 `fetch` を新設していないことを確認する
  - サーバー状態の真実の源泉が React Query に維持され、公開メモデータを Zustand へコピーしていないことを確認する
  - helmet セキュリティヘッダー・既存レート制限の方針を破壊していないことを確認する
  - 本フェーズの変更が既存テスト・リント・型チェックを破壊せず品質ゲートを通過することを確認する
  - _Requirements: 6.1, 6.2, 6.4, 6.5_
