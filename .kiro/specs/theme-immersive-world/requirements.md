# Requirements Document

## Project Description (Input)

theme-immersive-world: テーマを「色替え」から「ユーザーが帰ってくる"入る世界"」へ進化させる。第一スライスとしてフラッグシップの森(mori)テーマを、アプリを開いた瞬間から全体がその世界になる完全没入＋作り込まれた質感でフルリライトする。

## 背景・目的

Mosakuの差別化軸は「ハイセンスなデザイン・テーマの世界観」。だが現状、テーマの世界観はメモ本文面（.memo-title / .memo-content）だけに乗っており、アプリを開いた瞬間に目に入るメモ一覧・ホーム・サイドバー・ヘッダーは Tailwind 標準の「ありきたりな既製品UI」のまま。そのため「好きな世界に帰ってくる」引力が生まれず、メモを見に行く動機が弱い（書く労力自体はMCP連携で解決済みのため、残る本丸は"見に行きたくなるビジュアル"の欠如）。

本スペックは、テーマを「開いた瞬間から全体に適用される"入る世界"」と再定義し、(1)没入スコープの全体拡張 と (2)既製品っぽくない作り込まれた質感 を【セット】で実現する。この2つが揃って初めて「この世界に帰ってきたい」という動機になる、という仮説に基づく。

## スコープ（森1本の垂直スライス・深さ優先）

- 森(mori)テーマを対象に、玄関（メモ一覧・ホーム・サイドバー・ヘッダー）から本文まで一貫して世界観が乗る「完全没入」を実現する。
- UI質感を「ありきたりなMaterial/Tailwind既製品」から脱却させる：テクスチャ・奥行き・余白設計・タイポグラフィ・マイクロインタラクションを作り込む（参照イメージ＝ポケモンカードアプリの"新しく清潔感のある質感"。色ではなく質感と作り込み）。
- この過程で「シェル全体にテーマを安全に適用する基盤」と「質感コンポーネント層」を確立し、残り3テーマ（海・夜・朝）がトークン差し替えで相乗りできる土台にする。

## 必須制約（過去のロールバックを再発させない）

- 既存spec mosaku-brand-theme の Phase A で「テーマ全体適用」を実装したが、白背景ヘッダーのナビ文字までテーマ文字色になり文字が消失してロールバックした経緯がある。→ 生の色を直当てするのではなく、セマンティックトークン（surface / on-surface 等の意味単位）で設計し、コントラスト・可読性を要件として保証する。
- 外部JSライブラリ追加ゼロ（軽量メモアプリ方針／バンドル肥大の回避）。
- login-visual-redesign 由来の森の資産（深緑グラデ・霧・葉エフェクト）を再利用する。
- 他テーマ（海・夜・朝）および既存の認証・メモ編集ロジックに影響を与えない。

## 非スコープ

- 海・夜・朝の全体没入＋質感フルリライト（本スペックで作る基盤の上に後続スペックで展開）。
- 色替えだけの新規テーマ追加。
- バックエンド／DBスキーマの変更（テーマはCSS本体＋メタデータのみのまま）。

## Introduction

本スペックは、Mosaku のテーマを「メモ本文だけの色替え」から「アプリを開いた瞬間に全体が切り替わる"入る世界"」へ進化させる。第一スライスとしてフラッグシップの森(mori)テーマを対象に、玄関（メモ一覧・ホーム・サイドバー・ヘッダー）から本文まで一貫して世界観が乗る**完全没入**と、ありきたりな既製品 UI を脱した**作り込まれた質感**を【セット】で実現する。

現状、シェルのルート要素にはすでに `.theme-root` が付与され森の背景グラデーション・霧は全域に描画されているが、玄関の各面は不透明な既定 UI 地（Tailwind の `bg-white`）と標準の文字色で世界の上にフタをしており、開いた瞬間に「入る世界」になっていない。本スペックはこのフタを外し、玄関までテーマを届かせる。

ただし過去 `mosaku-brand-theme` Phase A で「全体適用」を試みた際、`.theme-root button` などの要素型セレクタが Tailwind ユーティリティ（`text-gray-600` 等）と同詳細度で競合し、白背景ヘッダーのナビ文字が消失してロールバックした（friction log: ヘッダー文字消失）。本スペックは同じ轍を踏まないために、生の色を直当てするのではなく**セマンティックトークン（surface / on-surface 等の意味単位）**で設計し、コントラスト・可読性を要件として保証する。あわせて、この過程で確立する「シェル適用基盤」と「質感コンポーネント層」を、残り3テーマ（海・夜・朝）が**トークン差し替えだけで相乗りできる土台**にする。

本スペックは森1本の垂直スライス（深さ優先）であり、外部 JS ライブラリ追加ゼロ・バックエンド/DB スキーマ不変・他テーマおよび既存の認証/メモ編集ロジック非干渉を必須制約とする。

### Requirement Grouping

- **基盤（ロールバック回避の前提条件）**: Requirement 1（セマンティックトークン） / Requirement 3（可読性・コントラスト）
- **没入スコープの全体拡張**: Requirement 2（玄関の全体没入） / Requirement 5（玄関〜本文の世界の連続性・森資産再利用）
- **脱・ありきたり質感**: Requirement 4（質感コンポーネント層）
- **横展開の基盤化**: Requirement 6（海・夜・朝の相乗り）
- **制約遵守**: Requirement 7（非干渉・軽量・データ不変）

## Requirements

### Requirement 1: セマンティックトークン基盤（ロールバック回避の前提条件）

**Objective:** As a Mosaku 開発者, I want シェル全域の配色を生の色ではなく意味単位のセマンティックトークン（surface / on-surface 等）で扱いたい, so that 白背景に文字色を直当てして文字が消失した過去のロールバックを構造的に防げる

#### Acceptance Criteria

1. The Mosaku Theme System shall 背景面・前景文字・面上の補助文字・境界・アクセントなどの役割を表すセマンティックトークン（例: surface / surface-variant / on-surface / on-surface-variant / outline / accent）を定義する
2. When 森テーマが適用された時, the Mosaku Theme System shall 玄関各面の配色を上記セマンティックトークン経由で解決し、コンポーネント側に生のカラーリテラルを直接記述しない
3. The Mosaku Theme System shall 各 surface トークンに対して可読性を満たす on-surface トークンを対（ペア）で定義し、面と前景文字を常にペアで扱う
4. The Mosaku Theme System shall 玄関の彩色を、Tailwind ユーティリティと詳細度衝突しない方式（トークンを面側に適用し、`.theme-root button` のような要素型セレクタで汎用 HTML 要素の文字色を直接上書きしない）で実装する
5. The Mosaku Theme System shall セマンティックトークンを、森以外のテーマ（海・夜・朝）も同一の役割名で値を差し替えられる共通語彙として定義する

### Requirement 2: 玄関の全体没入（シェル全域へのテーマ適用）

**Objective:** As a Mosaku ユーザー, I want アプリを開いた瞬間に目に入るメモ一覧・ホーム・サイドバー・ヘッダーが森の世界になっていてほしい, so that 「好きな世界に帰ってきた」と感じてメモを見に行きたくなる

#### Acceptance Criteria

1. When ユーザーが森テーマを有効にしてアプリを開いた時, the Mosaku App Shell shall メモ一覧・ホーム・サイドバー・ヘッダーを含む玄関領域を森の世界観（背景・面・文字・アクセント）で描画する
2. While 森テーマが有効な状態で, the Mosaku App Shell shall 玄関領域の不透明な既定 UI 地（Tailwind の `bg-white` 等）をテーマ surface に置き換え、テーマ背景がシェル全域に届くようにする
3. When 森テーマでアプリが初期表示される時, the Mosaku App Shell shall 未テーマの白いシェルが一瞬見えるちらつき（FOUC）なしにテーマ済みの玄関を描画する
4. The Mosaku App Shell shall デスクトップ（DesktopLayout）・モバイル（MobileLayout）双方で玄関の全体没入を成立させる
5. The Mosaku App Shell shall 玄関への没入適用によって既存のナビゲーション導線・操作機能（画面遷移・各種ボタンの動作）を破壊しない

### Requirement 3: 可読性・コントラストの保証（ヘッダー文字消失の再発防止）

**Objective:** As a Mosaku ユーザー, I want 全体没入後もヘッダーやサイドバーの文字・アイコンがはっきり読める, so that 世界観のために実用性（読めること）が犠牲にならない

#### Acceptance Criteria

1. While 森テーマが玄関に適用された状態で, the Mosaku App Shell shall すべての玄関面（ヘッダー・サイドバー・一覧・ホーム）のテキストと背景のコントラスト比を WCAG AA（本文 4.5:1 以上・大きな文字 3:1 以上）以上に保つ
2. When 森テーマが適用された時, the Mosaku App Shell shall ヘッダー・サイドバーのナビゲーション文字・アイコンが背景に溶けて消失しない視認可能な状態を保つ
3. While 森テーマが有効な状態で, the Mosaku App Shell shall フォーカスリング・選択中項目・ホバー状態などの状態表示を、背景と区別可能なコントラストで提示する
4. The Mosaku App Shell shall プレースホルダ・無効状態・補助テキストなどの低強調テキストも判読可能な最小コントラストを下回らないようにする
5. Where 自動テストでコントラストを検証できる箇所がある場合, the Mosaku Theme System shall 主要な surface×on-surface ペアのコントラスト比を検証するテストを備える

### Requirement 4: 脱・ありきたり質感（質感コンポーネント層）

**Objective:** As a Mosaku ユーザー, I want メモ一覧やボタン・カードが Tailwind/Material の既製品っぽさを脱した作り込まれた質感であってほしい, so that 「このアプリは丁寧に作られている」と感じて触り続けたくなる

「質感」を測れる5軸（テクスチャ・奥行き・余白・タイポグラフィ・マイクロインタラクション）に分解して定義する。参照イメージはポケモンカードアプリの清潔感ある質感（色ではなく作り込み）。

#### Acceptance Criteria

1. The Mosaku App Shell shall 玄関の主要面（カード・サイドバー・ヘッダー・一覧アイテム）に、単色べた塗りではないテクスチャ／マテリアル処理（微細なグラデーション・層・質感トークン）を適用する
2. The Mosaku App Shell shall 前景と背景の階層を、エレベーション（奥行き）設計によって意図的に表現する（Tailwind 既定の素の影に依存しない）
3. The Mosaku App Shell shall 玄関面に意図的な余白・間（スペーシングスケール）を与え、詰まった既製品然としたレイアウトを脱する
4. The Mosaku App Shell shall ブランド署名フォント（游明朝）を軸にした字階層・字間・行間で玄関のタイポグラフィを整える
5. When ユーザーがボタン・カード・一覧アイテム等の操作要素にホバー／フォーカス／押下した時, the Mosaku App Shell shall そのフィードバックをマイクロインタラクション（状態遷移・モーション）で提示する
6. While `prefers-reduced-motion: reduce` が有効な状態で, the Mosaku App Shell shall 質感由来のモーション（マイクロインタラクションのトランジション等）を停止し、テクスチャ・奥行き・余白・タイポの静的な質感は維持する

### Requirement 5: 玄関と本文をつなぐ世界の連続性（森資産の再利用）

**Objective:** As a Mosaku ユーザー, I want 玄関から本文まで切れ目なく同じ森の世界が続いてほしい, so that どこを見ても一つの世界に入っている没入感が途切れない

#### Acceptance Criteria

1. The Mosaku Theme System shall login-visual-redesign 由来の森の資産（深緑グラデーション背景・霧レイヤー・葉エフェクト）を再利用し、玄関の世界観の土台とする
2. While 森テーマが有効な状態で, the Mosaku App Shell shall 玄関（一覧・ホーム・サイドバー・ヘッダー）と本文面（.memo-title / .memo-content）の間で背景・配色・タイポの世界観を連続させ、シェルと本文の境目で世界が断絶しないようにする
3. When 森テーマが適用されている時, the Mosaku Theme System shall 既存の森 JS エフェクト基盤（effectKey + canvas、選択時のみ動的ロード、reduced-motion／エディタフォーカス／タブ非表示／マウスアイドルの4条件で自動停止）の挙動を壊さず共存する
4. The Mosaku Theme System shall 既存の本文面テーマ（.memo-content 配下の見出し・引用・コード等のスタイル）の見た目を後退させない

### Requirement 6: 海・夜・朝の相乗り基盤化（トークン差し替えで展開可能に）

**Objective:** As a Mosaku 開発者, I want 森で確立したシェル適用基盤と質感コンポーネント層を、海・夜・朝がトークン差し替えだけで相乗りできる土台にしたい, so that 後続スペックで3テーマ分の地雷を踏まずに横展開できる

#### Acceptance Criteria

1. The Mosaku Theme System shall シェル適用基盤と質感コンポーネント層を、テーマ固有値をセマンティックトークンとして外出しした構造で実装する
2. Where 海・夜・朝の各テーマが同一のセマンティックトークン語彙に値を与える場合, the Mosaku Theme System shall シェル／質感コンポーネントのコードを変更せずに当該テーマの世界観を玄関へ適用できる設計とする
3. The Mosaku Theme System shall 明テーマ（朝）でも暗テーマ（森・海・夜）でも可読性が成立するよう、トークン契約（surface と on-surface のペア）を明暗反転に耐える形で定義する
4. The Mosaku Theme System shall 本スペックでは値の実装対象を森に限定し、海・夜・朝の値実装と全体没入は後続スペックに委ねる（基盤の受け皿のみを用意する）

### Requirement 7: 非干渉・軽量・データ不変の制約遵守

**Objective:** As a Mosaku ユーザー兼開発者, I want 全体没入と質感の作り込みが他テーマ・既存機能・バンドル軽量性を損なわずに実現される, so that 軽量メモアプリとしての品質と既存資産が守られる

#### Acceptance Criteria

1. When ユーザーが森以外のテーマ（海・夜・朝）を選択した時, the Mosaku Theme System shall 本スペック実装前と同一の視覚的結果をレンダリングし、玄関への没入や質感処理を適用しない
2. The Mosaku Theme System shall 外部 JS ライブラリを新規追加せず、React と既存フック／既存エフェクト資産・CSS のみで全体没入と質感を実現する
3. The Mosaku Theme System shall テーマの実体を CSS 本体＋メタデータのままとし、バックエンド／DB スキーマを変更しない
4. The Mosaku Theme System shall 全体没入と質感の実装が既存の認証フローおよびメモ編集ロジックに副作用を与えないことを保証する
5. While 森以外のテーマが選択されている状態で, the Mosaku Theme System shall 森専用の質感／没入のための追加 DOM・CSS・RAF を読み込まず、非森ユーザーの初期バンドルサイズを本スペック実装前から増加させない
