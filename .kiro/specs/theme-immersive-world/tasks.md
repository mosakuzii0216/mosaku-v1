# Implementation Plan

## theme-immersive-world

> 本 spec はフラッグシップの森（mori）1 本の垂直スライス（深さ優先）。**CSS 契約（Task 1〜2）を先に固定**し、状態・起動（Task 3）／玄関サーフェス改修（Task 4）／森リッチパック（Task 5）を契約に従って並行トラックで進め、Task 6〜7 で共存・統合を検証する。過去ロールバック（ヘッダー文字消失）の再発を構造的に防ぐため、玄関の彩色は必ずセマンティックトークン経由・要素型セレクタ禁止を全タスクで遵守する。値の正しさ（コントラスト AA）は RED テストで機械化し人間が承認する。外部 JS ライブラリ追加ゼロ・DB スキーマ不変・他テーマ非干渉を不変則とする。

- [x] 1. セマンティックトークン契約（CSS Layer1 / render-blocking）

- [x] 1.1 セマンティックトークン語彙と中立既定値を定義する
  - 背景面・前景文字・補助文字・境界・アクセント・状態・フォーカス・奥行き・余白・タイポの役割を表すトークン語彙を定義する
  - すべての surface 系に可読性を満たす on-surface 系をペアで定義し、面と前景文字を常にペアで扱える契約にする
  - 中立既定値を現行の生 Tailwind と一致させ、テーマ未設定時に現状と同一の見た目を保つ
  - 役割名を 4 テーマ共通の語彙とし、明（朝想定）でも暗（森）でも成立する明暗反転耐性のある契約にする
  - 要素型セレクタを使わず `data-theme` 属性＋クラスで解決する方式を前提に置く
  - _Requirements: 1.1, 1.3, 1.4, 1.5, 6.3, 7.1_

- [x] 1.2 コントラスト AA 機械検証テストを作成する（RED）
  - 主要 surface×on-surface ペアのコントラスト比を検証するテストを用意する
  - 半透明 surface を「通常床（深緑ベース）」と「worst-case 床（最明の白透け）」の両端に合成し、合成色でも本文 4.5:1 以上・低強調 4.5:1（または大字 3:1）以上を満たすことを検証する
  - フォーカスリング・状態層・accent×on-accent の非テキスト/テキストコントラストも検証対象に含める
  - 森の実値は次タスクで確定するため、この時点ではテスト失敗（RED）でよい
  - 1.1 のトークン語彙に依存するため 1.1 完了後に実施する
  - _Requirements: 3.1, 3.3, 3.4, 3.5_

- [x] 1.3 森の全色・構造トークン値を実装し他 3 テーマの受け皿を置く（GREEN）
  - 森テーマに全色・構造トークン値（色・状態・奥行き・余白・タイポ）を実装し、コントラストテストを通す
  - surface の透過率を「白床に合成しても本文 AA」を満たす下限で固定し、背後の生きた背景がどれだけ明滅しても AA を割らない値域にする
  - テクスチャ・noise・本文面の重量物はこの層に含めず Layer3 へ分離する（色トークンの単一の源泉をこの層に保つ）
  - 海・夜・朝はコメント placeholder のみとし、値実装と全体没入は後続スペックに委ねる
  - 1.2 のテストを GREEN にする工程のため 1.2 完了後に実施する
  - _Requirements: 6.1, 6.2, 6.4_

- [x] 2. 質感プリミティブ層（CSS Layer1 / render-blocking）

- [x] 2.1 (P) 質感 5 軸の構造クラスを実装する
  - Task 1 完了後に着手。別ファイル（primitives 層）のため Task 3 と並行実施可
  - トークンを読む theme-neutral な構造クラス（面の地・パネル/カード・ナビ要素・入力・ボタン）を過剰設計せず最小セットで提供する
  - 面の地を半透明＋backdrop にし、背後の生きた背景を透かして玄関〜本文の連続性の土台にする
  - パネル/カードに奥行き（エレベーション）とテクスチャを与え、素の影に依存しない意図的な階層表現にする
  - ナビ要素・入力にホバー/フォーカス/選択の状態トークンとフォーカスリングを与え、背景と区別可能にする
  - 意図的な余白スケールと、游明朝を軸にした字階層・字間・行間を与える
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 5.2, 3.3_

- [x] 2.2 マイクロインタラクションと reduced-motion 停止を実装する
  - 操作要素のホバー/フォーカス/押下のフィードバックをトランジションで提示する
  - `prefers-reduced-motion: reduce` でトランジション・アニメーションを停止し、テクスチャ・奥行き・余白・タイポの静的質感は維持する
  - 2.1 と同一ファイルを拡張するため 2.1 完了後に実施する
  - _Requirements: 4.5, 4.6_

- [x] 3. シェルテーマ状態と起動時適用（FOUC 回避）

- [x] 3.1 (P) コア変数マップと即時適用ユーティリティを用意する
  - Task 1 完了後に着手。TypeScript 群のため Task 2 と並行実施可
  - slug → コア変数（surface / on-surface / 地色）の極小マップを用意する（森のみ実値、他 3 は placeholder）
  - 永続テーマの同期読み出しと、ルート要素への slug 設定＋コア変数適用（critical 反映）を行うユーティリティを用意する
  - アクセント・境界・奥行き等は Layer1 バンドルが first paint で供給するため本マップには含めず、半テーマ窓を作らない
  - _Requirements: 2.3, 6.4_

- [x] 3.2 アプリ単位シェルテーマの永続ストアを実装する
  - 選択テーマ（id と slug）を localStorage 同期で保持する UI 状態ストアを用意し、初期値を first render で確定する
  - 選択変更時に localStorage 書き込み・critical 即時反映・ストア更新を行う
  - localStorage 利用不可（プライベートモード等）・破損値では例外を投げず in-memory／中立既定にフォールバックする
  - サーバー状態は持たず、保持するのは「どのテーマを選んだか」の UI 選択のみとする
  - 同期読み出し・永続・critical 反映・破損フォールバックをユニットテストで固定する
  - 3.1 の即時適用ユーティリティに依存するため 3.1 完了後に実施する
  - _Requirements: 2.1, 7.3_

- [x] 3.3 (P) 起動時インラインブートと CSP 適合を実装する
  - 3.1 完了後に着手。ルート HTML 改修のため 3.2／3.4（別ファイル）と並行実施可
  - first paint 前に永続テーマを同期読み出しし、ルートの slug と地色を確定して白フラッシュを消す
  - 同等ロジックを runtime 切替でも再利用し（属性既設なら no-op）DRY にする
  - CSP がインラインスクリプトを許容するか初手で検証し、不可なら最小の静的ブートファイルへ退避する（新規 JS ライブラリは追加しない）
  - _Requirements: 2.3_

- [x] 3.4 アクティブテーマ解決を文脈→シェル床→null に更新する
  - 文脈テーマ（ノートブック/メモ）→シェル床→null の優先順位で解決するよう既存解決を更新する
  - シェル床は選択 id をサーバー状態キャッシュで解決し、キャッシュ未充足時は slug 由来の最小テーマで CSS／エフェクト解決を途切れさせない
  - 優先順位とキャッシュ未充足フォールバックのユニットテストを更新する
  - 3.2 のストア選択を消費するため 3.2 完了後に実施する
  - _Requirements: 2.1, 1.5_
