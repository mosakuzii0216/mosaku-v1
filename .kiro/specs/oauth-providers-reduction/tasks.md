# Implementation Plan

> 対象: OAuth プロバイダを Google / X / Apple の3種へ削減（LINE / GitHub 廃止）。
> 方式: design.md の Option C（subtractive 除去 ＋ 各サイド provider 列挙の単一真実源化）。
> 進め方: 品質モデル（`quality.md`）に従い各作業で「正しさ（廃止後の期待挙動）をテストで先に固定 → 除去」。1 サブタスク ≒ 1〜3 時間 / 1 Todo = 1 Commit。
>
> **並行実行**: バックエンド除去（Task 1）／フロントエンド除去（Task 2）／データモデル（Task 3）／設定・ドキュメント（Task 5）は境界が分離しており `(P)` 同士を並行実行可能。UI とエンドポイントの runtime 整合は最終統合（Task 6）で確認する。

- [x] 1. バックエンド: 廃止プロバイダの認証経路除去と provider 真実源の縮約
- [x] 1.1 provider 真実源を有効3プロバイダへ縮約し型を導出（削除漏れ検出器の確立）
  - 有効プロバイダ集合を Google / X / Apple の3つに縮約し、これを唯一の真実源として provider 型（union）を導出型へ置き換える
  - 廃止プロバイダ専用の型・プロファイル/ユーザー表現インターフェースを除去する
  - 登録開始のバリデーションが有効3プロバイダのみを受理し、LINE / GitHub 指定を 400 で弾くことをテストで固定する
  - 型の縮約により残存する LINE / GitHub 参照が型エラーとして可視化され、1.2〜1.5 の除去作業リストになる（本メジャータスク完了時にビルド緑）
  - _Requirements: 1.3, 2.2_

- [x] 1.2 廃止プロバイダの認証エンドポイントと Guard を除去
  - LINE / GitHub の認証開始・コールバックのエンドポイントを除去し、未定義ルート化して 404 を返すようにする
  - 廃止プロバイダ用の認証 Guard を除去する
  - 除去したルートが 404 を、登録開始への廃止プロバイダ指定が 400 を返すことを統合テストで固定する
  - _Requirements: 2.1, 2.2_
  - _Contracts: OAuth Endpoint Layer（API: 404 / 400）_

- [x] 1.3 廃止プロバイダの Passport Strategy と DI 登録を除去
  - LINE / GitHub の Passport Strategy を除去し、認証モジュールの登録（provider / strategy / guard）から切り離す
  - Strategy / Guard 無しで DI コンテナが解決することをテストで確認する
  - _Requirements: 2.2, 2.3_

- [x] 1.4 廃止プロバイダのログイン/登録処理を除去し email 起点合流を維持
  - 廃止プロバイダのログイン・招待登録処理を除去する（識別子列自体は保持し、書き込み経路のみ消滅させる）
  - 残プロバイダで同一メールの既存アカウントに合流し、旧識別子が上書きされる継続アクセス動線が維持されることをテストで固定する
  - Google の識別・ログイン経路が無影響であること（`oauthId` を GitHub と共用するが subtractive 変更で不変）を確認する
  - _Requirements: 2.2, 3.1, 3.2, 4.2_

- [x] 1.5 廃止プロバイダの設定 getter と認可URL生成分岐を除去
  - 廃止プロバイダの環境変数 getter と、認可 URL 生成の provider 分岐から LINE / GitHub を除去する
  - 残プロバイダの認可 URL 生成が無回帰であることをテストで確認する
  - 廃止プロバイダの環境変数が未設定でも残プロバイダに影響なく起動すること（該当コード消滅により自明に成立）を確認する
  - _Requirements: 2.2, 2.3_

- [ ] 2. (P) フロントエンド: provider 真実源の集約とログイン導線の削減
  - Task 1（バックエンド）と別境界のため並行実行可。サブタスクは 2.1 → 2.2 / 2.3 の順（真実源に依存）
- [ ] 2.1 (P) FE の provider 型と有効 id 一覧を単一真実源へ集約
  - 複数箇所に重複する provider 型定義を単一モジュールへ集約し、有効 id 一覧を Google / X / Apple に統一する（招待フローの provider 型もこの真実源に追従させる）
  - Task 1 とはファイル境界が分離しており並行実行可
  - _Requirements: 1.3_

- [ ] 2.2 廃止プロバイダの provider 設定・起動関数・認証コンテキストを除去
  - provider 設定レコード・ラベル・アイコン設定から LINE / GitHub を除去する
  - 廃止プロバイダの認証起動ユーティリティと認証コンテキストのログイン関数を除去する
  - 2.1 の真実源に依存するため 2.1 の後に着手する
  - _Requirements: 1.2, 2.2_

- [ ] 2.3 ログイン画面と招待登録画面のボタンを有効3プロバイダへ削減
  - ログイン画面（ログイン / 新規登録の両モード）で表示ボタンを Google / Apple / X の3種のみにする
  - 招待登録画面で「他の方法」を展開しても LINE / GitHub が現れないようにする
  - 両画面のいずれの導線でも LINE / GitHub ボタンが表示されないことを UI テストで固定する
  - _Requirements: 1.1, 1.2, 1.3_

- [ ] 3. (P) データモデルの非破壊保持と識別子の健全性文書化
  - `lineId` 列と格納済みデータを破壊的マイグレーションで削除せず保持し、スキーマに「LINE 廃止後も監査 / 復旧用に列保持」の説明コメントを追記する（マイグレーションは生成しない）
  - `githubId` 列が存在せず GitHub が `oauthId` を Google と共用し判別列が無いこと、撤去が Google に無影響であることをスキーマ上に文書化する
  - 残プロバイダの識別子（`oauthId` / `appleId` / `xId`）の一意制約が無変更で維持されることを確認する
  - Task 1 とは別ファイル（スキーマ）のため並行実行可
  - _Requirements: 4.1, 4.3, 5.1, 5.2_
  - _Contracts: User Data Model（State / 無変更）_

- [ ] 4. 未使用となった OAuth 依存パッケージの除去
  - 廃止プロバイダの Passport Strategy 依存パッケージと自作の型 shim を除去し、ビルド・型チェックが緑であることを確認する
  - `passport-twitter` 系（X 認証）は本スコープ外として据え置く
  - Task 1.3（Strategy 除去）完了後に着手する（Strategy が当該依存を参照しているため並行不可）
  - _Requirements: 2.2_

- [ ] 5. (P) 設定ファイルとドキュメントの整合
  - `.env.example` から廃止プロバイダ（LINE / GitHub）の環境変数ブロックを削除し、有効3プロバイダに整合させる
  - OAuth セットアップ／デプロイ関連ドキュメントから LINE / GitHub 記述を削除し有効3プロバイダへ更新する
  - CLAUDE.md の環境変数リストを有効プロバイダ（Google / X / Apple）に合わせて更新する
  - Task 1〜4 とは別ファイル群のため並行実行可
  - _Requirements: 6.3, 6.4_

- [ ] 6. 最終回帰確認と廃止プロバイダ残存ゼロ検証
  - コードベース全体で LINE / GitHub 参照の残存がゼロであることを機械的（grep + 型チェック）に確認する
  - 残プロバイダ（Google / X / Apple）のログイン／新規登録フローが従来どおり成功すること、および他プロバイダを持たない既存ユーザーのパスワード再設定による継続アクセス手段が維持されることを確認する
  - 廃止エンドポイントが実際に 404 を返すことを実測で確認する
  - バックエンド・フロントエンドの自動テストスイートが全て緑であることを確認する（廃止プロバイダ関連テストは削除 / 更新済み）
  - _Requirements: 3.3, 6.1, 6.2_
