# Requirements Document

## Introduction

mosaku ホーム画面（ランチャー＋ダッシュボード）機能。ユーザーが認証済みの状態で mosaku を開いたときに最初に表示される画面。「新規メモを書く」「前のメモに追記する」という2つの主要な開く動機に直接応えるプル型ナビゲーションを提供する。

通知を一切使わず、開いたときに迎えるプル型で設計する。ホーム画面の性格は「発射台型（ランチャー）＋見渡し型（ダッシュボード）が9割、書かせる型が1割」。並行開発中の `memo-display-mode`（没入表示モード）と導線を統合し、「書きたくなる → 書く瞬間が気持ちいい」の体験ループを形成する。

## Requirements

### Requirement 1: ホーム画面の基本表示

**Objective:** ユーザーとして、mosaku を開いたときに目的のアクションへ素早く辿り着けるホーム画面が表示されることで、何を書くか・どこへ行くかを迷わず起動できる

#### Acceptance Criteria

1. When 認証済みユーザーがアプリを起動または最初のルートを訪問する, the ホーム画面 shall ランチャー＋ダッシュボード画面を最初の画面として表示する
2. The ホーム画面 shall 現在アクティブなテーマの CSS 変数に従ったスタイルで描画する
3. The ホーム画面 shall デスクトップ・モバイルの両レイアウトに対応したレスポンシブデザインで表示する
4. While サーバーデータを取得中である, the ホーム画面 shall スケルトン UI またはローディングインジケーターを各セクションに表示する
5. If データ取得がエラーになった場合, the ホーム画面 shall エラーメッセージと再試行手段を表示し、他の独立したセクションの表示には影響を与えない

### Requirement 2: 新規メモ作成（ヒーロー①）

**Objective:** ユーザーとして、ホーム画面から1アクションで新規メモを書き始められることで、書くモチベーションが高い瞬間に摩擦なく開始できる

#### Acceptance Criteria

1. The ホーム画面 shall 「新しいメモを書く」アクションを画面上部の主要 CTA として他の要素より視覚的に強調して表示する
2. When ユーザーが「新しいメモを書く」CTA をタップまたはクリックする, the ホーム画面 shall 新規メモ作成画面へ即座に遷移する
3. The ホーム画面 shall 「新しいメモを書く」CTA を1タップで到達できる位置に配置する

### Requirement 3: 最近のメモ一覧（ヒーロー②）

**Objective:** ユーザーとして、最近編集したメモをホーム画面で確認し、1タップで続きを書けることで、「前のメモに追記したい」という主要な開く動機を満たせる

#### Acceptance Criteria

1. The ホーム画面 shall 直近に更新されたメモを最大5件、横スクロール可能なカード形式で表示する
2. When ユーザーが最近のメモカードをタップまたはクリックする, the ホーム画面 shall 対応するメモの編集画面へ遷移する
3. The ホーム画面 shall 各メモカードにタイトルまたは本文冒頭テキストと最終更新日時を表示する
4. The ホーム画面 shall 最近のメモデータを React Query 経由で取得し、Zustand へのデータコピーを行わない
5. If 最近のメモが0件である場合, the ホーム画面 shall 空状態メッセージを表示し新規作成 CTA へ誘導する

### Requirement 4: 今週の活動サマリー

**Objective:** ユーザーとして、今週書いたメモの件数を確認できることで、自然な達成感を得ながら書いた記録を見渡せる

#### Acceptance Criteria

1. The ホーム画面 shall 今週（月曜〜日曜）に作成または更新したメモの件数を表示する
2. The ホーム画面 shall 件数を「今週 N個 書いたよ」という形式の文言で提示する
3. The ホーム画面 shall 今週の件数データを React Query 経由で取得する
4. If 今週の件数が0件である場合, the ホーム画面 shall 空状態を示すメッセージを表示する（強制感・プレッシャーを与えない文言を使用する）

### Requirement 5: 書いた日カレンダー表示

**Objective:** ユーザーとして、書いた日をカレンダー上のドットで視覚的に確認できることで、ストリークを押し付けることなく「書いた日の記録」として自然に振り返れる

#### Acceptance Criteria

1. The ホーム画面 shall 直近の期間（当月または直近4週間）を週単位のグリッドで表示し、メモを書いた日をドット（点）でマークする
2. The ホーム画面 shall 書いた日の情報を React Query 経由で取得する
3. The ホーム画面 shall 炎アイコン・連続日数カウンター等のストリーク強調表現を使用せず、書いた日の記録として中立的なデザインで表示する
4. The ホーム画面 shall 書いた日の算出に既存メモの `createdAt` または `updatedAt` フィールドを使用する

### Requirement 6: ノートブック一覧

**Objective:** ユーザーとして、件数付きのノートブック一覧をホーム画面から確認・選択できることで、特定のノートブックへ書きに行く動線を持てる

#### Acceptance Criteria

1. The ホーム画面 shall ユーザーが所有するノートブックを件数付きの一覧として表示する
2. When ユーザーがノートブック項目をタップまたはクリックする, the ホーム画面 shall 選択したノートブックのメモ一覧へ遷移する
3. The ホーム画面 shall ノートブックデータを React Query 経由で取得し、Zustand へのデータコピーを行わない
4. If ノートブックが0件である場合, the ホーム画面 shall ノートブック作成への誘導を表示する

### Requirement 7: 今日のお題（低優先度）

**Objective:** ユーザーとして、書くきっかけとなるお題を控えめに見られることで、書くネタに迷ったときの出発点を得られる

#### Acceptance Criteria

1. The ホーム画面 shall 「今日のお題」セクションを画面下部に他のセクションより小さいサイズで表示する
2. The ホーム画面 shall お題を静的なテキストリストからランダムに1件選択して表示する
3. When ユーザーがお題テキストをタップまたはクリックする, the ホーム画面 shall お題のテキストを初期入力に含んだ新規メモ作成画面へ遷移する
4. If お題の取得または表示が失敗した場合, the ホーム画面 shall お題セクションのみを非表示にし他のセクションに影響を与えない
