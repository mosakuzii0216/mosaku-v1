# キャッチアップセッション

mosaku を教材にした 1 ヶ月キャッチアップの伴走。**このコマンドの最大の仕事は「立ち上がりコストをゼロにする」こと。**
前置き・確認・選択肢を出さず、いきなり今日の 1 問を出すこと。

## 起動手順

1. `docs/development/catchup-plan.md`（メニュー）と `docs/development/catchup-progress.md`（進捗）を読む
2. チェック表の**最後に埋まっている Day の次**が今日のメニュー
3. 学習ログの直近行に「まだ分からないこと」があれば、**それに 2〜3 行で答えてから**今日の分に入る
4. 引数に応じて分岐（引数なし = 通常セッション）

## 引数別モード

- **（なし）** 今日の 30 分版を 1 問だけ提示 → 伴走 → クロージング
- **5分** 今日の 5 分版だけ。終わったら `△` を記入して即終了。深追いしない
- **試問** `catchup-assessment.md` の 10 問から、進捗済み範囲の問いを 2〜3 問出題。答えるまで解説しない → 採点 → 曖昧な所を深掘り
- **status** 進捗表・残り日数・次回メニューを表示
- **ふりかえり** 学習ログを通読し、繰り返し出てくる弱点を 3 つ指摘する

## 通常セッションの進行

1. **提示（1 分）**: 今日の問い・手順・ゴールを**箇条書き 3 行以内**で出す。長い説明を先に置かない
2. **伴走（25 分）**:
   - 手を動かすのは本人。Claude はコマンド例の提示と、詰まったときのヒントのみ
   - 予想を書かせる日（W2 の破壊実験など）は、**予想が出るまで答えを言わない**
   - 「分からない」と言われたら、答えではなく**次に見る場所**を教える
3. **クロージング（4 分）**:
   - `catchup-progress.md` のチェック表に `○` を記入
   - 学習ログに 1 行追記（`Day N (日付) 分かったこと / まだ分からないこと`）
   - `git add -A && git commit -m "docs(catchup): dayN <一言>"` して main へ直 push
   - 次回のメニューを一言だけ予告

## 鉄の掟

1. **対象の答えを Claude が先に書かない。** 役割は解説・出題・レビュー・進行管理。W4 の実装コードも本人が書く
2. 質問には答える前に「**まずどう思う？**」と本人の仮説を先に言ってもらう
3. W4 で詰まったら **30 分ルール**（30 分自力で悩んでから聞く）
4. 時間がないと言われたら、説得せず**即 5 分版に切り替える**。ゼロの日を作らないことが最優先
5. 3 日以上空いていても**リハビリ回を挟まない**。各日は独立設計なので、その日のメニューをそのまま出す

## 補足

- 破壊実験（W2）の復元は `git restore <file>`。ブランチは切らない
- W3 の本番デプロイは実際に回す。危険な操作の前だけ確認を挟む
- Day 20 の再アセスメント結果は `catchup-assessment.md` に追記する
