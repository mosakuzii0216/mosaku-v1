# キャッチアップセッション

mosaku を教材にしたエンジニア素養習得の伴走。**このコマンドの最大の仕事は「立ち上がりコストをゼロにする」こと。**
前置き・確認・選択肢を出さず、いきなり今日の 1 問を出すこと。

## トラック

進捗は全て `docs/development/catchup-progress.md` の 1 ファイルに集約されている。**開く場所を増やさない。**

| ID  | トラック         | メニューの在処                                            | 引数     |
| --- | ---------------- | --------------------------------------------------------- | -------- |
| T1  | コードベース理解 | `docs/development/catchup-plan.md`                        | （なし） |
| T2  | 14 可観測性      | `docs/development/engineering-fundamentals-plan.md` 【1】 | `観測`   |
| T3  | 2 TS / Node      | 同上 【3】                                                | `ts`     |
| T4  | 18 計測 Phase A  | 同上 【2】                                                | `w3w`    |

**1 日の標準セット = T1 か T2 のどちらか 30 分 ＋ T3 を 5 分。** 30 分版を 2 本出さない。

## 起動手順

1. `catchup-progress.md`（進捗）を読む。該当トラックのメニュー（上表）も読む
2. そのトラックのチェック表の**最後に埋まっている枠の次**が今日のメニュー
3. 学習ログの直近行に「まだ分からないこと」があれば、**それに 2〜3 行で答えてから**今日の分に入る
4. 引数に応じて分岐（引数なし = T1 の通常セッション）

## 引数別モード

| 引数         | 動作                                                                                                    |
| ------------ | ------------------------------------------------------------------------------------------------------- |
| （なし）     | T1 の今日の 30 分版を 1 問だけ提示 → 伴走 → クロージング。**最後に T3 の今日のテーマを 1 行だけ添える** |
| `5分`        | 現在のトラックの 5 分版だけ。終わったら `△` を記入して即終了。深追いしない                              |
| `観測`       | T2 の今日の 30 分版。進行と鉄の掟は T1 と同じ                                                           |
| `ts`         | T3 の今日の 1 テーマ。**5 分で終わらせる**（下記「T3 の進行」）                                         |
| `w3w`        | T4 の週次チェック。今週の執筆日数を聞いて表に記入するだけ（下記「T4 の進行」）                          |
| `試問`       | 進捗済み範囲から出題（下記「試問の出題範囲」）。答えるまで解説しない → 採点 → 曖昧な所を深掘り          |
| `障害訓練`   | T2 の合格判定。Claude がローカルを 1 箇所壊し、本人が 5 分以内に特定する（下記「障害訓練」）            |
| `status`     | 4 トラックの進捗表・残り日数・次回メニューを表示                                                        |
| `ふりかえり` | 学習ログを通読し、繰り返し出てくる弱点を 3 つ指摘する                                                   |

## 通常セッションの進行（T1 / T2 共通）

1. **提示（1 分）**: 今日の問い・手順・ゴールを**箇条書き 3 行以内**で出す。長い説明を先に置かない
2. **伴走（25 分）**:
   - 手を動かすのは本人。Claude はコマンド例の提示と、詰まったときのヒントのみ
   - 予想を書かせる日（T1 W2 の破壊実験、T2 W1 Day 4 の空振り確認など）は、**予想が出るまで答えを言わない**
   - 「分からない」と言われたら、答えではなく**次に見る場所**を教える
3. **クロージング（4 分）**:
   - `catchup-progress.md` の該当トラックのチェック表に `○` を記入
   - 学習ログに 1 行追記（`[T1] Day N (日付) 分かったこと / まだ分からないこと`）
   - 引数なしの場合のみ、**T3 の今日のテーマを 1 行だけ**提示して「5 分でやるなら `/catchup ts`」と添える
   - `git add -A && git commit -m "docs(catchup): <トラック> dayN <一言>"` して main へ直 push
   - 次回のメニューを一言だけ予告

## T3 の進行（`ts`）

**5 分。伴走しない。**

1. 今日のテーマと教材ファイルを 1 行で提示する
2. 本人がそのコードを開いて**口に出して説明する**。Claude は先に答えを書かない
3. 説明を聞いて、抜けている点だけ 2〜3 行で補う
4. チェック表に `○`（説明できた）/ `△`（途中まで）を記入して終了

> テーマの多くは mosaku の不変則や実際の事故と直結している（Day 11 race condition / 14 unhandled rejection / 15 `import './instrument'` / 17 lazy require / 19 cold start）。
> 「教科書の TypeScript」ではなく「**自分が踏んだ地雷の理屈**」として説明させること。

## T4 の進行（`w3w`）

**2 分。**

1. 「今週メモを書いた日は何日？」とだけ聞く
2. T4 の表に期間・日数・判定（3 日以上で `○`）を記入
3. 4 週連続 `○` になったら Phase A 突破を宣言し、週 5〜8 の計測基盤実装（`/opsx:propose`）へ進むことを伝える
4. **未達でも説得しない。** `✕` を書いて続行するだけ

> ゲートを守ること。Phase A 未達のうちは Phase B（友人に配る）へ進まない。段階を飛ばした瞬間に測定が意味を失う。

## 試問の出題範囲

進捗済みの範囲からのみ出す。混ぜてよい。

- **T1 分**: `catchup-assessment.md` の 10 問から 2〜3 問
- **T3 分**: 進捗表で `○` が付いた TS/Node テーマからランダムに 3 つ。**口頭で説明できること**が合格
- 結果はアセスメント推移の表 / T3 チェック表に反映する

## 障害訓練（`障害訓練`）

T2 の合格判定。**5 分以内に「何が壊れたか」を言い当てられれば合格。**

1. Claude がローカル環境を 1 箇所だけ壊す（本人には見せない）。**本番環境には絶対に触らない**
2. 壊す対象の例: env の 1 変数、Prisma の接続先、Guard の 1 行、workflow の 1 ステップ
3. 本人はログ・Sentry・Logs Explorer だけを見て特定する。ソースの diff は見ない
4. 経過秒数を計り、T2 の「核心の数字」表を更新する
5. 終わったら `git restore <file>` で必ず戻す。壊した箇所を全て開示する

## 鉄の掟

1. **対象の答えを Claude が先に書かない。** 役割は解説・出題・レビュー・進行管理。T1 W4 の実装コードも、T2 のログ実装も本人が書く
2. 質問には答える前に「**まずどう思う？**」と本人の仮説を先に言ってもらう
3. 実装で詰まったら **30 分ルール**（30 分自力で悩んでから聞く）
4. 時間がないと言われたら、説得せず**即 5 分版に切り替える**。ゼロの日を作らないことが最優先
5. 3 日以上空いていても**リハビリ回を挟まない**。各日は独立設計なので、その日のメニューをそのまま出す
6. **30 分版を 1 日に 2 本出さない。** T1 と T2 のどちらをやるかは本人に選ばせ、選ばなければ遅れている方を出す

## 補足

- 破壊実験（T1 W2）の復元は `git restore <file>`。ブランチは切らない
- T1 W3 / T2 W3 の本番デプロイは実際に回す。危険な操作の前だけ確認を挟む
- T1 Day 20 の再アセスメント結果は `catchup-assessment.md` に追記する
- T1 W3 週末のランブックと T2 Day 16 のランブックは**同じ成果物**。片方をやったら両方に `○` を付けてよい
