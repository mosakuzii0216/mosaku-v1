# /review — 良い警官・悪い警官 並列レビュー

現在の変更に対して、**2体のレビュアーを並列で起動** し、その結果を人間（あなた）が裁判官として読むためのレポートにまとめます。

設計思想は `.kiro/steering/quality.md`（AI時代の品質モデル）を参照。
役割分担は **基本分離＋セキュリティ/認可だけ意図的に両者に被せる** 方針です。

---

## 手順

### 1. レビュー対象を確定

引数があればそれを対象に、なければ作業ツリーの差分を対象にします。

- **引数なし**: 未コミットの変更すべて。**追跡ファイルの差分（`git diff HEAD`）と未追跡ファイル（`git ls-files --others --exclude-standard`）の和集合**を対象にする。
  - ⚠️ `git diff HEAD` だけでは **未追跡（新規）ファイルが落ちる**。新規ファイルこそレビューが要るので、必ず未追跡分を足すこと。実務上は `git add -N`（intent-to-add）で未追跡を diff に乗せてから `git diff HEAD` を取ると、新規ファイルの中身も差分として読める。
  - **対象が空（追跡・未追跡とも変更ゼロ）の場合は、黙ってフォールバックせず停止する。** 「レビュー対象がありません。コミット範囲・ファイル・PR 番号を引数で指定してください」と人間に返す。直前コミット（`HEAD~1 HEAD`）を勝手にレビューすると、無関係な変更に PASS を出す事故になるため、自動フォールバックはしない。
- **引数あり**: 指定ファイル / コミット範囲 / PR 番号。
  - コミット範囲: そのまま `git diff <range>` を対象にする。
  - PR 番号: `gh pr diff <番号>` で差分を取得する（`gh` が使えない場合はその旨を人間に伝える）。

対象の差分を確認し、変更ファイルの一覧を把握する。**実際にレビュアーへ渡したファイル一覧を統合レポートの冒頭に明記し**、取りこぼしを人間が検知できるようにする。

### 2. 2体を「並列」で起動（重要）

**必ず1つのメッセージ内で2つの Task を同時に呼び出し、並列実行すること。** 直列にしない。独立した2つの視点を混ぜないことが、悪い警官の忖度を防ぐ。

- `code-reviewer`（😇 良い警官）: 規約準拠・既知パターンの照合
- `adversarial-reviewer`（😈 悪い警官）: 本番で壊れるシナリオの破壊検証

それぞれに「レビュー対象の差分 / ファイル一覧」（**未追跡ファイルを含む**）を渡す。

> 🔍 **並列実行の自己監査**: 統合レポートに「2体を単一メッセージで並列起動した」と明記する。直列に劣化していないかを人間が検知できるようにするため。1体ずつ順に起動したらこのコマンドは失敗とみなす。

> 🪞 **自己参照のときの注意**: レビュー対象が**このレビュー基盤ファイル自体**（`.claude/agents/*.md` / `.claude/commands/review.md` / `.kiro/steering/quality.md`）の場合、各エージェントは「自分の定義＝レビュアーとしての行動規範」と「レビュー対象＝今読んでいる diff」を**メタ階層として明確に分離**すること。判定ルールを対象仕様と取り違えない。

### 3. 統合レポートを出力（あなたは仲介者であって判定者ではない）

2体の結果を改変せずに統合する。**ここで勝手にLGTMを出さない。** 最終判定は人間が下す。

```markdown
# 🧑‍⚖️ レビュー結果（裁判官＝あなたが最終判定）

## レビュー対象（取りこぼし検知用）

- 対象の決め方: [引数なし=未コミット全変更 / コミット範囲 / PR番号]
- レビュアーに渡したファイル: [実際に渡した全ファイルを列挙。未追跡ファイルを含むこと]
- 起動方式: 2体を単一メッセージで並列起動した [Yes/No]

## 総合シグナル

| レビュアー          | 判定               |
| ------------------- | ------------------ |
| 😇 良い警官（規約） | [PASS / NEEDS-FIX] |
| 😈 悪い警官（破壊） | [PASS / BLOCK]     |

> ルール: 悪い警官が BLOCK、または良い警官が NEEDS-FIX なら、原則マージしない。
> ただし **最終判断は人間** が行う（誤検知・許容リスクの判断は人間の責務）。

## 😈 悪い警官の指摘（先に読む — 致命傷から潰す）

（adversarial-reviewer のレポートをそのまま）

## 😇 良い警官の指摘（規約）

（code-reviewer のレポートをそのまま）

## ⚖️ 裁判官への論点

- 今すぐ直すべき Critical: [...]
- 人間の判断が要るグレー: [...]
- 悪い警官が「自信がない」と言った穴: [...]
```

### 4. 次アクションを問う

人間に「① 指摘を直す / ② 一部を許容してマージ / ③ さらに深掘り」を尋ねる。
勝手にコードを修正しない（このコマンドはレビュー専任。修正は別途指示を受けてから）。

---

## 禁止事項

- 2体を直列で起動すること（必ず並列）
- AI が勝手にマージ可否を最終決定すること（判定は人間）
- レビュアーの指摘を要約で薄めること（特に Critical はそのまま見せる）
