# 新機能開発コマンド

新機能「$ARGUMENTS」の開発を開始します。

以下の8ステップを順番に実行してください。途中でスキップせず、すべて完了させてください。

---

## ステップ1: 準備とコンテキスト設定

- 機能名: 「$ARGUMENTS」
- 日付: 本日の日付（YYYYMMDD形式）
- ステアリングディレクトリ: `.steering/{日付}-{機能名}/`

## ステップ2: プロジェクト理解

以下を確認し、プロジェクトの全体像を把握してください:

1. `CLAUDE.md` を読み、アーキテクチャ・規約を理解
2. `docs/` ディレクトリで関連ドキュメントを確認
3. 既存のステアリング（`.steering/` 内）があれば参照

## ステップ3: 既存パターン調査

Grep / Glob を使い、以下を調査してください:

- 今回の機能に関連する既存コード
- 類似機能の実装パターン（モジュール構成、DTO、テスト）
- 再利用できるユーティリティやサービス

## ステップ4: 計画フェーズ（ステアリング生成）

Skill('steering') を使ってステアリングファイルを生成してください。

以下の3ファイルが `.steering/{日付}-{機能名}/` に作成されます:

1. `requirements.md` - 要件定義
2. `design.md` - 設計
3. `tasklist.md` - タスクリスト

**重要**: 生成後、ユーザーに内容を確認してもらい、承認を得てから次に進んでください。

## ステップ5: 実装ループ

`tasklist.md` を開き、タスクを上から順に実装してください。

**ルール:**

- 各タスク完了時に `[ ]` → `[x]` に更新する
- 全タスクが `[x]` になるまで繰り返す
- タスクが大きすぎる場合はサブタスクに分割して `tasklist.md` に追記する
- 「時間がかかる」等の理由でスキップしない

## ステップ6: コードレビュー

全タスク完了後、code-reviewer エージェントを起動してレビューを実施してください。

```
Task('code-reviewer') で今回の変更をレビュー
```

**Critical** な指摘がある場合は修正し、再レビューを行ってください。

## ステップ7: 品質検証

以下のコマンドを実行し、すべてパスすることを確認:

**バックエンド変更がある場合:**

```bash
cd backend && npm run test && npm run lint && npm run build
```

**フロントエンド変更がある場合:**

```bash
cd frontend && npm run lint && npm run build
```

**Prisma スキーマ変更がある場合:**

```bash
cd backend && npx prisma generate
```

失敗した場合は修正し、再実行してください。

## ステップ8: 振り返り

`tasklist.md` の末尾に振り返りセクションを記録してください:

- 実装完了日
- 計画と実績の差分
- 技術的な学び
- プロセス上の改善点
- 次回への改善提案

---

## 完了条件

以下がすべて満たされたら完了です:

- [ ] tasklist.md の全タスクが `[x]`
- [ ] code-reviewer のレビューで Critical 指摘なし
- [ ] テスト・lint・ビルドがすべてパス
- [ ] 振り返りが tasklist.md に記録済み
