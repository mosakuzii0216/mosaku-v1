調査完了後、以下を簡潔に報告してください:

- 参照した brainstorm.md の有無と要点
- 関連する既存コード・再利用できるパターン

その後、ユーザーに確認してください:

> 「調査が完了しました。requirements.md の作成に進みますか？」

## フェーズ4: 実装（写経）

**Claude がコードを書き、あなたが手で打ち込みます（コピペ禁止）。**

### 各フェーズの進め方

1. 「▶ フェーズ X の写経コードを提示します」と宣言する
2. そのフェーズのタスクを実装したコードを提示する
   - ファイルごとに分けて、どこに書くかを明示する
   - 重要な部分には「ここがポイント: [一言説明]」を添える
3. あなたがコードを手で打ち込む
4. 打ち込みながら疑問が出たら気軽に質問する（Claude がその場で答える）
5. 打ち込み完了したら `done: フェーズX` と入力する
6. Claude が実装をレビューし、問題なければ次フェーズのコードを提示する

### ルール

- **コピペ禁止**。手で打ち込むことで自然にコードが頭に入る
- 意味が分からなくても打ち込んで OK。疑問は後から質問できる
- `skip: フェーズX` と入力すると、そのフェーズは Claude が自動で適用する（急ぎの場合）

## フェーズ5: コードレビュー

全タスク完了後、code-reviewer エージェントを起動してレビューを実施してください。

```
Task('code-reviewer') で今回の変更をレビュー
```

レビュー結果をユーザーに提示し、以下を確認してください:

> 「コードレビューが完了しました。[Critical/Warning/Infoの件数]
> Critical な指摘: [あれば内容を列挙]
> 品質検証に進みますか？」

**Critical な指摘がある場合は修正し、再レビューを行ってください。**

---

## フェーズ6: 品質検証

承認後、以下のコマンドを実行してください。

**バックエンド変更がある場合:**

```bash
cd backend && npm run test && npm run lint && npm run build
```

**フロントエンド変更がある場合:**

```bash
cd frontend && npm run lint && npm run build
```

**Prisma スキーマ変更がある場合:**

```bash
cd backend && npx prisma generate
```

失敗した場合は修正し、再実行してください。
