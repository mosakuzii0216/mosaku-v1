# 週次品質監査 — 無人実行の手順書

毎週金曜 18:00（JST）にクラウドの定期エージェントから起動されるときの手順書。
定期エージェント側のプロンプトは「このファイルを読んで従え」とだけ指示し、
**中身はこのファイルで管理する**（変更履歴を git で追えるようにするため）。

人間がその場におらず、途中で止められない前提で書かれている。

## 1. まず読むもの

同じディレクトリの `SKILL.md` を読み、**その手順と制約に完全に従う**こと。
今回は SKILL.md の「**無人実行モード**」の節が適用される実行である。

このファイルと SKILL.md が矛盾する場合は **SKILL.md を優先**する。
ここに書くのは、クラウド実行環境に固有の事情だけ。

## 2. 環境セットアップ

監査はテスト実行を伴うため、先に依存関係を用意する。

```bash
npm ci                              # リポジトリルート
cd backend && npx prisma generate   # 無いと backend のテストと型チェックが落ちる
```

**DB は使えない。** DB 接続を必要とする E2E テストは実行できないので、その場合は
ユニットテストと型チェックの範囲で検証し、**その旨をレポートに明記**する。

## 3. 監査の実行

SKILL.md の手順 1〜4 をそのまま実行する。

```bash
bash .claude/skills/weekly-quality-audit/scripts/find-candidates.sh
# → 候補を 1 つだけ選定 → 変更 → 下記でテスト
bash .claude/skills/weekly-quality-audit/scripts/run-affected-tests.sh <変更ファイル...>
```

**ロジック変更・バグ修正・機能追加は禁止。** 純粋な品質返済のみ。

## 4. 成果の出し方

- ブランチ `chore/weekly-audit-YYYY-MM-DD` を切る（YYYY-MM-DD は実行日）
- SKILL.md のコミットメッセージ規約に従ってコミットする
- `gh pr create` で main 向けの PR を作成する
- **PR 本文には SKILL.md 手順 5 の形式のレポート全文をそのまま入れる。**
  この本文が GitHub Actions 経由で Slack へ転送され、通知の中身そのものになる
- PR タイトルはコミットメッセージと同じにする
- **main へは絶対に push しない**

### 「発見したが手を出さなかったこと」は手を抜かない

SKILL.md の「記入基準」に従うこと。テストを追加した場合は、対象ファイルの
public メソッド／export された関数を列挙し、カバーしたもの・しなかったものを
必ず明示する。**1 つでも未カバーなら「なし」とは書けない。**

## 5. PR を作ったら終了する

以下は**指示されていない限り行わない**:

- 追加のスケジュール／check-in の登録（自分を再起動する予約を作らない）
- PR の購読・CI の追跡・マージまでの見届け
- プッシュ通知の送信（通知は `.github/workflows/audit-notify.yml` が Slack へ送る）

CI・AI レビュー・マージは GitHub 側の仕組みが担当する。エージェントの仕事は
**PR を出すところまで**。

## 6. 中止条件

どれかに当たったら **PR を作らずに終了**し、理由を報告する。

| 条件                         | 対応                                         |
| ---------------------------- | -------------------------------------------- |
| 候補がゼロ                   | 何も作らず「対象なし」と報告して終了         |
| テストが落ちた               | 変更を破棄し、落ちた事実と内容を報告して終了 |
| 変更してよいか自信が持てない | 手を出さず、候補として書き残して終了         |

## 最重要

**迷ったら手を出さない。** 人間がその場におらず途中で止められないため、対話実行より
保守的に判断すること。空振りの週があって構わない。
**無理に候補をひねり出すことが最大の失敗。**
