# ステアリング管理スキル

このスキルは3つのモードで動作します。コンテキストに応じて適切なモードを選択してください。

---

## モード1: ステアリングファイル作成（計画フェーズ）

新機能の要件定義・設計・タスクリストを作成します。

### 手順

1. `CLAUDE.md` を読み、プロジェクトの規約とアーキテクチャを確認
2. `docs/` ディレクトリで関連ドキュメントを確認
3. 以下のテンプレートを読み込む:
   - `./templates/requirements.md`
   - `./templates/design.md`
   - `./templates/tasklist.md`
4. `.steering/{YYYYMMDD}-{機能名}/` ディレクトリを作成
5. テンプレートのプレースホルダーを具体的な内容に置き換えて各ファイルを生成

### 生成時の注意

- **requirements.md**: 曖昧な表現を避け、受け入れ基準を具体的に記述する
- **design.md**: 新規ファイルと修正ファイルを明確に分ける。Prisma スキーマ変更がある場合は必ず記載する
- **tasklist.md**: タスクは1つ30分以内で完了できる粒度に分割する。依存関係のあるタスクはフェーズで順序を制御する

---

## モード2: 実装管理

ステアリングファイルに基づいて実装を管理します。

### MUST（必須）

- `tasklist.md` を常に参照しながら実装する
- タスク完了時に `[ ]` → `[x]` に更新する
- 実装中に追加タスクが発生したら `tasklist.md` に追記する
- 全タスクが `[x]` になるまで作業を継続する

### NEVER（禁止）

- `tasklist.md` を見ずに実装を進める
- 未完了タスクを残して作業を終了する
- タスクをスキップする（大きすぎる場合はサブタスクに分割する）

### NestJS バックエンド実装時のチェックポイント

- Module に新しい Provider/Controller を登録したか
- DTO に `class-validator` デコレータを設定したか
- 保護エンドポイントに `@UseGuards(JwtAuthGuard)` を付けたか
- ユーザーリソースに `AuthorizationService.checkOwnership()` を実装したか
- Prisma スキーマ変更後に `npx prisma generate` を実行したか

### React フロントエンド実装時のチェックポイント

- API呼び出しは `API_BASE_URL` と `AuthTokenManager` を使用しているか
- サーバー状態は React Query で管理しているか
- クライアント状態は Zustand ストアで管理しているか

---

## モード3: 振り返り記録

実装完了後、`tasklist.md` の末尾に以下を追記します。

```markdown
## 実装後の振り返り

### 実装完了日
[YYYY-MM-DD]

### 計画と実績の差分

**計画と異なった点**:
- [変更内容と理由]

**新たに必要になったタスク**:
- [追加タスクと理由]

### 学んだこと

**技術的な学び**:
- [技術的知見]

**プロセス上の改善点**:
- [改善点]

### 次回への改善提案
- [提案内容]
```
