## 方針・前提

| 項目               | 決定事項                                                                         |
| ------------------ | -------------------------------------------------------------------------------- |
| 登録方式           | **招待制を永続維持**。招待コードをDMに含めて営業する形式                         |
| 権限モデル         | **ADMIN / USER の2種類のみ**（PREMIUMロール廃止）                                |
| 招待コード種別     | **通常コード**（1回使い切り）と**キャンペーンコード**（1コードでN名まで登録可）  |
| 収益化             | 友人フェーズまで完全無料。友人ヒアリング後にノートブック買い切りモデルを判断     |
| フィードバック     | アプリ内フォーム → Slack通知                                                     |
| ランディングページ | デザイン・テーマのショーケースを前面に出した視覚重視のLP                         |
| SNS営業チャネル    | **X（Twitter）** + **Instagram**（両方新規アカウント作成）                       |
| 差別化軸           | **ハイセンスなデザイン・テーマ数の多さ・ブランディングの雰囲気**                 |
| テーマ目標         | **50テーマ**（現在7、43追加。週5時間込みで現実的な数）                           |
| 障害対応           | Sentryエラー検知 → AIが自動で初期調査しSlack通知 → 必要なら即時対応              |
| 開発ペース         | **週5時間**（月約20時間、テーマ作成込み）                                        |
| 開発プロセス       | **cc-sdd（仕様駆動開発）**。全ての機能追加・修正は仕様定義→承認→実装の順で進める |

### Phase 1: ドッグフーディング（5月〜7月）

**目標: 毎日Mosakuだけを使い、不便な点をcc-sddで仕様化して潰す。**

> **摩擦記録の運用ルール（2026-04-23 確定）**
>
> `dogfooding-friction-log` 専用仕組みは archive（`.kiro/specs/_archived/`）。永続価値のある機能が残らないため、既存機能だけで運用する方針に切り替え:
>
> - `Friction Log` ノートブックを手動で 1 個作成し、摩擦はその配下に通常メモで記録
> - severity は本文冒頭に `🔥 blocker` / `⚠️ major` / `💭 minor` / `✨ nice-to-have` を 1 行で明示
> - 領域は既存タグで分類（例: `area:editor` / `area:theme` / `area:auth` / `area:mobile`）
> - spec 化済みは `#spec-done`、却下は `#rejected` タグで管理
> - 金曜に `Friction Log` ノートブックを眺めて Top3 を選定 → `/kiro:spec-init` で起票
> - 汎用価値がありそうな「ノートブック単位のテンプレート」機能は、必要になった時点で別 spec として再起票

## cc-sddワークフロー（全開発の標準フロー）

```
新しい機能・修正が発生
  ↓
/kiro:spec-init "機能の説明"
  ↓
/kiro:spec-requirements → 人間が承認
  ↓
/kiro:spec-design → 人間が承認
  ↓
/kiro:spec-tasks → 人間が承認
  ↓
/kiro:spec-impl（タスク番号）→ TDD（RED→GREEN→REFACTOR）
  ↓
/kiro:validate-impl で整合性確認
  ↓
コミット（1 Todo = 1 Commit）
```

> **原則**: 承認なしに実装しない。「とりあえず作ってみる」はしない。
