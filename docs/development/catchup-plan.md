# キャッチアップ計画（1ヶ月・全体感編）

> v1（14,400行の写経計画）は 2 回作って 2 回とも 0 行で終わった。原因は「時間が確保できない」＋「初めの一歩が重い」。
> よって v2 は**内容より立ち上がりコスト**を設計する。旧版は [\_archive/catchup-plan-v1-shakyo.md](./_archive/catchup-plan-v1-shakyo.md)。

## ゴール（唯一の合格判定）

[catchup-assessment.md](./catchup-assessment.md) の 10 問を **0/10 → 10/10**。
全部「説明できるか」を問う設問なので、訓練も「思い出して言葉にする」に寄せる。

## 4 つの設計制約

| 制約               | 実装                                                                 |
| ------------------ | -------------------------------------------------------------------- |
| 30 秒で始められる  | 1 日 = 1 つの問いだけ。この計画書は 1 ページ                         |
| 前日に依存しない   | 各日が独立完結。3 日空いてもその日のメニューから普通に再開           |
| ゼロの日を作らない | 全日に **5 分版**。時間がない日はそれで「やった」判定                |
| 開く場所は 1 つ    | 進捗も学習ログも [catchup-progress.md](./catchup-progress.md) に集約 |

## 進め方

平日 30 分 + 週末 2h（計 約 18h）。セッション開始は `/catchup`。

```
追う（W1） → 壊す（W2） → 運用する（W3） → 作る（W4）
```

| 4    | `npx prisma studio` で該当レコードを見る + Prisma のクエリログを ON にして実 SQL を見る                                        | Prisma Studio で Memo テーブルを眺める                       |

## W2 壊す — 不変則 5 本

「なぜこの設計？」に答えられるようになる週。**わざと破って**、壊れ方で理解する。
毎回: 破る → 何が起きるか**予想を書く** → テスト実行で答え合わせ → `git restore` で戻す。

| Day  | 破る不変則                                                                                           | 5 分版                                   |
| ---- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 6    | 所有権チェック（`AuthorizationService.validateOwnership`）を外す → 他人のメモが取れるか              | 該当 spec のテスト名を全部読む           |
| 7    | サーバー状態を Zustand にコピーする → 何が壊れるか                                                   | `frontend/src/stores/` の中身を確認      |
| 8    | `apiClient` を通さず直 `fetch` する → `credentials` 事件の再現                                       | `api.ts` の `credentials` 指定箇所を探す |
| 9    | Soft Delete を物理削除に変える → 何が失われるか                                                      | `trashedAt` の使用箇所を grep            |
| 10   | グローバル JWT Guard を外す / `@Public()` を付ける → 認証の穴                                        | `@Public()` が付いた API を列挙          |
| 週末 | 5 本の「なぜ」を自分の言葉で文章化 + アセスメント Q7（テーマの保存先）/ Q8（招待コード検証）の穴埋め | —                                        |

## ルール

1. **Claude は解説・出題・レビューのみ。** 対象コードは自分で書く
2. 質問するときは**先に自分の仮説を言う**（「〜だと思うんだけど合ってる？」）
3. 時間がない日は迷わず 5 分版。**ゼロの日を作らないことが最優先**
4. 週末が潰れた日はスキップして翌週へ。取り返さない
