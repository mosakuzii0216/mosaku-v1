# エディタ体験の改善 の要件定義

## 概要

**目的**: メモを開いたときにテンションが上がり、すぐに書き始められる体験を提供する

**背景**:
- メモを開いてもデザインがイマイチでモチベーションが上がらない
- メモフォームをクリックしないと書き始められない（自動フォーカスがない）
- テーマシステムはあるが、「紙っぽい」「コードエディタっぽい」など書く気になる個性的なテーマが不足

**対象ユーザー**: 全ユーザー

---

## 機能要件

### 1. 自動フォーカス（メモを開いたらすぐ書ける）

- **説明**: 既存メモを選択した時も、エディタに自動フォーカスが当たり、クリックなしで書き始められる
- **受け入れ条件**:
  - [ ] メモ一覧からメモをクリックすると、エディタコンテンツエリアにフォーカスが当たる
  - [ ] 新規作成時も同様にフォーカスが当たる（既存動作の維持）
  - [ ] フォーカスはメモが切り替わるたびに適用される

### 2. 新テーマ「紙（kami）」の追加

- **説明**: 紙のノートに書いているような、温かみのあるデザインのテーマ
- **受け入れ条件**:
  - [ ] フォントはセリフ体（Noto Serif JP または Georgia）
  - [ ] 背景はクリーム色・オフホワイト系（#faf8f3 程度）
  - [ ] テキストカラーは温かみのある暗色（焦げ茶・ダークブラウン系）
  - [ ] ページ感（用紙のような box-shadow または border）を表現
  - [ ] テーマ選択画面で表示・選択できる

### 3. 新テーマ「コードエディタ（code）」の追加

- **説明**: VSCode風のコードエディタのような、シャープでクリーンなデザインのテーマ
- **受け入れ条件**:
  - [ ] フォントはモノスペース（Fira Code / JetBrains Mono / Consolas）
  - [ ] ダークバックグラウンド（#1e1e1e 程度）
  - [ ] テキストカラーは明るいグレー（#d4d4d4 程度）
  - [ ] アクセントカラーはVSCode青（#569cd6 程度）
  - [ ] border-radius は小さく（シャープな印象）
  - [ ] テーマ選択画面で表示・選択できる

---

## 非機能要件

- **パフォーマンス**: CSSファイル読み込みは既存の仕組みを利用（追加コストなし）
- **セキュリティ**: テーマはシステムテーマ（`isSystem: true`）として登録、改ざん不可
- **可用性**: テーマCSSが読み込めない場合はデフォルトスタイルにフォールバック（既存動作）

---

## 影響範囲

### 既存機能への影響
- `RichTextEditor` コンポーネント: `focusKey` プロップを追加（後方互換あり）
- `MemoEditor` コンポーネント: `autofocus` の渡し方を変更
- 既存テーマ（ao, aka, mori, kuro, siro）: 変更なし

### データベース変更
- Prismaスキーマ変更なし
- `themes` テーブルに2レコード追加（マイグレーションSQL）

---

## 受け入れ基準

- [ ] メモをクリックすると自動的にエディタにフォーカスが当たる
- [ ] 「kami」テーマを選択するとノートブックのエディタが紙っぽいデザインになる
- [ ] 「code」テーマを選択するとノートブックのエディタがコードエディタ風デザインになる
- [ ] 既存テーマが壊れない
- [ ] `npm run lint` と `npm run build`（frontend）がパスする
